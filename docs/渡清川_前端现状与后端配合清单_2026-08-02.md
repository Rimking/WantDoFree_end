## 1. 一句话结论

前端已把信息架构收口为 **「旅行 / 我的」双 Tab**，主闭环变成：

**新建旅程 → 规划 → 记一笔 → 游记工作台 → 模版中心 / 分享**

其中 **旅程 / 记录 / 计划 / 草稿 / 统计 / 分享票** 等主链路大多已有真实 API；真正卡住或需后端补强的，集中在：

1. **游记四态缺少服务端统一字段**（前端本地拼装）  
2. **模版出图管线未接**  
3. **Guide（手帐）与「游记」产品名、生成契约未统一**  
4. **会员支付 / 账号注销等仍为占位**  
5. **资料、足迹城市、POI 等字段语义需纠偏**

## 2. 信息架构（当前）

### 2.1 Tab

| Tab | 路径 | 说明 |
|-----|------|------|
| 旅行 | `pages/JourneyHome/index` | 主枢纽：足迹 + 快捷入口 + 旅程列表 |
| 我的 | `pages/ProfileHome/index` | 账户 / 游记 / 模版 / 分享 / 设置 |

中间 FAB：**新建旅程**（自定义 `AppTabBar`）。

已降为二级、不再占 Tab：

- 全局足迹地图 `MapHome`
- 会员 `MemberHome`（入口灰态，`SHOW_MEMBER=false`）
- 统计 / 花费各子页

### 2.2 主闭环

```
新建旅程
  → 规划（准备事项 checklist / 预定点 plan.places / 预算）
  → 进行中：记一笔（必须挂旅程，智能关联）
  → 游记工作台（四态：待补充 / 可生成 / 已生成 / 已分享）
  → 一键生成 Guide + 模版中心选模版分享
  → 我的分享 / ShareView
```

### 2.3 必须分清的三套「地点 / 产出」概念

| 概念 | 数据源 | 页面 | 含义 |
|------|--------|------|------|
| 预定打卡点 | `plan.places` | 行程地图、计划编辑 | 出发前预定清单 |
| 自由打卡 | `Recording.location` | 时间线、记一笔选位置 | 人在哪记哪，不回写 places |
| 草稿 vs 游记 | `/drafts/*` vs 工作台状态机 | DraftBox vs HandbookWorkbench | **草稿箱 ≠ 游记** |

> 实现约束已写入仓库规则：行程地图禁止混入记录里的 location。

## 3. 近期前端已落地能力

### 3.1 导航与首页

- Tab 4 → 2（旅行 / 我的）
- 首页：问候、空状态、足迹卡、快捷栏（**记一笔 / 游记 / 地图视图**）、旅程筛选横滑卡
- **去掉首页「成稿/游记」横向列表**（与快捷入口重复）；列表只在游记工作台看
- 地图 / 统计从 Tab 降为二级入口

### 3.2 记一笔智能关联

- 入口：`goRecordComposeSmart`（`src/lib/recordComposeEntry.ts`）
- 规则概要：
  - 1 个进行中旅程 → 直进
  - 多个进行中 → 轻量切换
  - 无旅程 → 引导创建
  - 仅已完成旅程时 → 可补记并提示新建
- 独立页：`RecordCompose`（内嵌 `RecordSheet`）
- 支持文 / 图 / 多段语音 / 位置 / 多笔花费

### 3.3 游记工作台（原「成稿」）

- 页面：`pages/HandbookWorkbench/index`
- 入口：首页快捷「游记」、我的「我的游记」、详情底栏「游记」、进行中旅程卡次按钮
- 四态（**前端本地计算**）：

| 阶段 | 条件（当前实现） | 主行动 |
|------|------------------|--------|
| 待补充 `need_more` | 记录数 &lt; 3 | 继续补充 |
| 可生成 `ready` | 记录数 ≥ 3 且无 Guide | 一键生成 |
| 已生成 `generated` | 有 Guide 未分享 | 预览 / 分享 |
| 已分享 `shared` | 有分享表现 | 查看分享 / 预览游记 |

- 阈值常量：`HANDBOOK_MIN_RECORDS = 3`（`src/lib/handbookStatus.ts`）
- Meta 拼装：前端对旅程拉 `guideApi.getByJourney` + `shareApi.getStats`（有并发上限）

### 3.4 模版中心

- 页面：`pages/TemplateCenter/index`
- 入口：我的「模板中心」、详情「分享」、结束旅程后引导
- 六套正式模版 T1–T6 + 「即将上线」占位
- 载荷：`ShareTemplatePayload`（`src/types/shareTemplate.ts`），由旅程 + 记录 + plan **本地拼装**
- **出图**：`exportShareTemplateImage` 仍返回「图片生成管线尚未接入」
- QR：占位组件，未接真实小程序码

### 3.5 我的页（M1–M6）

- 用户卡 → 资料编辑
- 足迹卡 → 统计首页
- 常用：我的游记 / 模板中心 / 我的分享（邀请入口代码保留但菜单已注释）
- 设置：帮助反馈、数据与隐私、定位开关、协议、关于
- 会员卡：灰态「即将开放」

### 3.6 命名对齐（成稿 → 游记）

| 产品对外 | 旧称 | 代码层现状 |
|----------|------|------------|
| 游记 / 游记工作台 | 成稿 | UI 已改；目录仍 `Handbook*` |
| 草稿箱 | 曾与成稿混淆 | `DraftBox` + `/drafts/*`，标题「草稿箱」 |
| 手帐 / Guide | 生成物预览 | `guideApi` / `GuideShare` 仍用 guide；部分文案仍写「手帐」 |

**建议对外统一「游记」；接口可继续叫 `guide`，但文档与字段语义要写清。**

## 6. 需要后端配合的事项（按优先级）

### P0 · 影响主闭环「游记」

| # | 需求 | 现状 | 建议 |
|---|------|------|------|
| 1 | **游记阶段字段** | 前端用记录数 + 多次拉 guide/share-stats 拼四态 | 旅程或专用接口返回：`handbookPhase` / `recordCount` / `hasGuide` / `shareSummary`；阈值 3 建议可配置 |
| 2 | **生成契约统一** | 「一键生成」走 `guideApi.create`（模板参数常为 `basic`）；模版中心 T1–T6 是另一套前端渲染 | 明确：Guide 生成 vs 分享海报是否同一管线；至少约定 `templateId`、字段映射、异步任务状态 |
| 3 | **模版出图** | 仅有前端结构组件 + 占位 export | 需要：服务端渲染 / 云函数出图 / 或客户端 canvas 规范 + 上传接口；返回图片 URL |
| 4 | **分享小程序码** | QR 占位 | 带 `journeyId` / `shareToken` 的码生成接口 |

### P1 · 数据语义与体验一致性

| # | 需求 | 现状 | 建议 |
|---|------|------|------|
| 5 | **足迹城市数** | 多用旅程 `destination` 字符串去重 | 统计接口给出真实足迹城市（或自由打卡城市）字段 |
| 6 | **资料字段** | `/me` 与 `/user/profile` 双源；本地保留 gender/birthday/identities 等 | 统一 profile 契约，避免刷新丢失扩展字段 |
| 7 | **checklist vs plan.checks** | 进度真源是 checklist；`toggleCheck` 注释勿用于卡片进度 | 后端废弃或只读兼容旧 checks，文档标明唯一真源 |
| 8 | **已完成旅程能否补记** | 详情页拦截；智能记一笔允许补记 | 产品定一条规则，前后端校验一致 |
| 9 | **POI 无 Key** | 返回 `mock_` 时前端 toast | 生产环境保证真实 POI；或明确降级协议 |
| 10 | **文案/资源命名** | UI「游记」、接口 `guide`、部分文案「手帐」并存 | 接口文档增加「游记 = Guide 产出物」对照表 |

## 7. Store 与本地策略（后端需知）

| Store | 职责 | 后端资源 |
|-------|------|----------|
| user | 登录、资料、配额、合规、定位开关 | auth / me / profile |
| journey | 列表 CRUD、active | journeys |
| recording | 时间线、sync | entries / records |
| plan | places、旧 checks、预算估 | plan |
| checklist | 准备事项真源 | checklist |
| destination | 目的地点 | destinations |
| expense | 花费与预算 | expense / budget |
| guide | 手帐缓存与生成 | guide / share-events |
| draft | 草稿箱 | drafts |

## 8. 技术侧注意（联调环境）

| 项 | 说明 |
|----|------|
| Pinia | `main.ts` 需 `import * as Pinia` 并 `return { app, Pinia }`；版本锁 2.1.7 |
| 合规弹层 | App 内 `ComplianceModal` 延后到 `onLaunch` 后挂载，规避小程序 `$vm` 竞态 |
| echarts | 小程序走 `lime-echart` UMD，避免整包打进 `vendor.js` |
| 功能开关 | `SHOW_MEMBER=false`；真机请关 `USE_MOCK` / 按需关 `DEV_LOGIN` |
| 自定义 Tab | 与 `pages.json` tabBar 双轨，改 Tab 需两边同步 |

## 11. 变更摘要（相对重构前，便于后端扫一眼）

| 变化 | 对后端的影响 |
|------|----------------|
| Tab 收口、会员入口关闭 | 会员接口可暂不优先；勿依赖 Tab 级流量 |
