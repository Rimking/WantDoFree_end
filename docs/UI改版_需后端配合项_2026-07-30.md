# UI 改版 · 需后端配合项盘点

> 对照范围：当前暂存改动（`RecordSheet` / `TimelineItem` / `Recording` 模型 / mappers）+ 近期首页改版（`feat：首页改版0.1`）  
> 产出目的：区分 **纯前端 UI** vs **必须后端改契约**，便于排期联调  
> 文档日期：2026-07-30

---

## 0. 结论摘要

本轮 UI 改动里，**真正会碰到接口/数据模型的只有「一条记录支持多段语音 + 多笔花费」**。  
首页改版、Tab、卡片样式、地点表单样式等 **不需要后端改动**。

| 优先级 | 项 | 说明 |
|--------|----|------|
| **P0** | 一条记录多笔花费 `expenses[]` | 现契约只有单笔 `expense`；前端只能「合并成一笔」上传，分类会丢 |
| **P0** | 一条记录多段语音 `voices[]` / 多 `audio` media | sync 已尝试写多段 audio；PATCH 仍是单 `audioUrl`；读侧需稳定回传全部段 |
| **P1** | 花费汇总 `count` / `byCategory` 语义 | 多笔落库后，应按「花费笔数/分类」统计，而非「含花费的 entry 数」 |
| **—** | 其余 UI | 无需后端 |

> **现状兜底**：前端已做兼容层（`voices`/`expenses` 本地优先；同步时压缩成旧字段）。不改后端也能「大致能用」，但 **多分类花费会失真、多语音在 PATCH 编辑链路不可靠、换端/重装后无法还原多笔明细**。  
> **后端进度（2026-07-30）**：P0/P1 已落地，见 `前端对接_多段语音与多笔花费_2026-07-30.md`。前端请去掉 note hack，改走 `expenses[]` / `audios|voices`。

## 2. P0：必须后端修改

### 2.1 一条记录多笔花费 `expenses[]`

#### 产品行为（前端已上）

用户在同一条记录里可连续添加多笔花费，例如：

- 餐饮 68 元 + 交通 12 元 + 门票 50 元  
- 时间线按 **多枚 Chip** 展示；本地汇总按 **笔数** 计入 `count`

#### 当前后端契约

| 接口 | 现状 |
|------|------|
| `POST /journeys/entries/sync` | 单对象 `expense: { amountCent, category, currency, note? }` |
| `POST /records/update` | 单对象 `expense`（传入即覆盖） |
| Entry 读模型 | 单对象 `expense` |

#### 前端临时策略（兼容，有损）

多笔时写入：

```json
{
  "expense": {
    "amountCent": 13000,
    "category": "food",
    "currency": "CNY",
    "note": "food:6800|transport:1200|ticket:5000"
  }
}
```

问题：

1. **分类汇总失真**：只保留首笔 `category`，其余埋进 `note`  
2. **重装/他端无法还原多笔列表**（读回只有 1 条）  
3. `expense-summary.byCategory` 与用户真实分类不一致

#### 建议契约

**读 / 写统一增加数组字段，保留单对象兼容：**

```ts
expense?: {
  amountCent: number
  category: string
  currency?: string
  note?: string
} | null

expenses?: Array<{
  amountCent: number
  category: string
  currency?: string
  note?: string
}>
```

规则建议：

| 规则 | 说明 |
|------|------|
| 优先 | 有 `expenses` 时以数组为准；`expense` 可作合计或首笔兼容 |
| 空值删除 | PATCH 传 `expenses: []` 或 `expense: null` 表示清空花费 |
| 金额 | 一律分；优先 `amountCent` |
| 校验 | 每笔 `amountCent ≥ 1`；`category` 沿用现有英文 key |

**涉及接口：**

- `POST /journeys/entries/sync`（entries[]）
- `POST /records/update`（PatchRecordDto）
- `POST /journeys/entries/list`、`POST /journeys/detail` 的 entry 读模型
- （可选）手帐 `guide.byCategory` 按多笔重算

### 2.2 一条记录多段语音

#### 产品行为（前端已上）

同一条记录可录多段语音；时间线可分别播放；标签展示「语音 · N 段」。

#### 当前后端契约

| 接口 | 现状 |
|------|------|
| sync | `voice: { url, durationSec }` **单对象** + `media[]` 可含 `kind: audio` |
| PATCH `/records/update` | `audioUrl` + `audioDuration` **单字段** |
| 读 | `audio` / `voice` 单对象；多段依赖 `media[]` 里多个 audio |

#### 前端已做 / 缺口

| 链路 | 前端行为 | 风险 |
|------|----------|------|
| sync 写 | 多段 remote 语音写入 `media[]`（多条 `kind: audio`），`voice` 仍填首段 | 需后端 **明确接受并持久化多条 audio media**，且 list/detail **按 sortOrder 全部返回** |
| PATCH 写 | store 已传 `voices`，但 `toRecordPatchBody` **只映射首段 `audioUrl`** | 编辑删段/增段 **落库不完整** |
| 读 | mapper 已从 `media[]` 过滤全部 audio → `voices[]` | 依赖后端 list 真的带回多段 |

#### 建议契约（二选一，推荐 A）

**方案 A（推荐，改动小）**

- 语音统一挂在 `media[]`，`kind: "audio"`，带 `durationSec`、`sortOrder`
- 废弃「只能一条」的隐含约束；`voice` / `audio` 仅作 **首段兼容字段**
- PATCH 增加覆盖式字段，例如：

```json
{
  "audios": [
    { "url": "https://...", "durationSec": 12 },
    { "url": "https://...", "durationSec": 8 }
  ]
}
```

或约定：`media` 全量覆盖时允许同时含 image + audio（与 sync 对齐）。

**方案 B**

新增显式字段：

```ts
voices?: Array<{ url: string; durationSec: number }>
```

sync / PATCH / 读模型三端一致；`voice` 继续作首段兼容。

**无论 A/B，PATCH 必须能：**

1. 覆盖多段（增删改）  
2. 传空数组 / null 清空全部语音  
3. 与图片字段互不误删（不要「只传 images 就把 audio 清掉」，除非文档明确全量 `media` 覆盖语义）

## 3. P1：建议后端对齐

### 3.1 花费汇总统计语义

前端本地汇总已改为：**按花费笔数** 计 `count`（一条记录 3 笔 → count+3）。

后端若仍按「含 expense 的 entry 数」计 `count`，多笔上线后会与前端/产品预期不一致。

**建议：**

| 字段 | 建议语义 |
|------|----------|
| `totalCent` | 所有花费金额之和（与多笔一致） |
| `count` | **花费笔数**（`expenses` 条数之和；无数组时仍算 entry 上的 1 笔） |
| `byCategory[].count` | 该分类下的笔数 |
| `byCategory[].amountCent` | 该分类金额之和 |

涉及：

- `POST /journeys/expense/summary`
- `POST /me/expense/summary`
- `POST /stats/expenses`（若暴露 count）

## 5. 前端临时兼容说明（给后端排期参考）

在后端未上线前，前端行为如下：

```
本地真相：Recording.voices[] / Recording.expenses[]
     │
     ├─ sync 写：voices → media[](audio)×N + voice=首段
     │           expenses → 合并为单 expense（金额合计，note 编码分类）
     ├─ PATCH 写：目前仍主要落首段 voice + 单 expense（voices/expenses 未进 Patch DTO）
     └─ 读：media 多 audio → voices[]；expense 单对象 → expenses 仅 1 项
```

上线后端多笔/多段后，前端需跟进（本仓库后续改动，非本次后端范围）：

1. `toRecordPatchBody` 映射 `voices` / `expenses`  
2. 去掉「多花费塞进 note」的 hack  
3. mapper 优先读 `expenses[]` / `voices[]`（或全量 audio media）

## 7. 接口改动草稿（便于直接开任务）

### sync entry 增量字段

```json
{
  "clientId": "rec-xxx",
  "content": "夜市",
  "media": [
    { "url": "https://cdn/a.jpg", "kind": "image" },
    { "url": "https://cdn/v1.mp3", "kind": "audio", "durationSec": 12, "sortOrder": 0 },
    { "url": "https://cdn/v2.mp3", "kind": "audio", "durationSec": 8, "sortOrder": 1 }
  ],
  "voice": { "url": "https://cdn/v1.mp3", "durationSec": 12 },
  "expenses": [
    { "amountCent": 6800, "category": "food", "currency": "CNY" },
    { "amountCent": 1200, "category": "transport", "currency": "CNY" }
  ],
  "expense": {
    "amountCent": 8000,
    "category": "food",
    "currency": "CNY",
    "note": "兼容合计"
  }
}
```

### PATCH `/records/update` 增量字段

```json
{
  "recordId": "...",
  "audios": [
    { "url": "https://cdn/v1.mp3", "durationSec": 12 },
    { "url": "https://cdn/v2.mp3", "durationSec": 8 }
  ],
  "expenses": [
    { "amountCent": 6800, "category": "food", "currency": "CNY" }
  ]
}
```

> 字段名可与后端现有命名规范对齐（`audios` vs `voices` vs 全量 `media`）；**关键是读写对称 + PATCH 可覆盖删除**。
