# 前端对接 · 记录新建：接口调整 + 图片上传调整（2026-08-20）

> **✅ 后端已实现并实测通过**：`POST /dream/v1/journeys/entries/create` 已上线，`entries/sync` 已下线（404）。
> 本文件聚焦**本次两处调整**，前端对照本文件改动即可，无需理解整条旧链路。
> 完整契约见 `前端对接_记录新建接口_entries_create_2026-08-20.md`（本次为增量修订，以前者为准时以本文件为准）。

---

## 0. 一句话

1. **接口调整**：新建记录时，媒体不再传 `media: [{url, kind, size}]`，改传 **`mediaIds: ["上传返回的id", ...]`**
2. **图片上传调整**：`uploadMedia` 里 **entry 类型媒体（图片+语音）一律跳过 ownerId**；前端把上传返回的 `id` 收集起来，保存时随 create 提交

---

## 1. 为什么调整

| 旧做法 | 问题 |
|---|---|
| 上传是独立接口（prepare → 上传 → confirm），confirm 已返回媒体 `id`；但保存记录时前端传 **url**，后端按 url/storageKey 匹配收养 | 绕了一圈；相对/绝对 URL 差异需兜底；url 可能被改写导致匹配失败 |
| 语音上传需要 entry 先存在 → 上传前先 sync 建 entry → 再 sync 一次（**两次保存调用**） | 复杂且多余 |

新做法：**上传返回 id，保存传 id，后端直接关联**——符合直觉，后端不再做任何 URL 匹配。

---

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `mediaIds` | 选 | array ≤20 | **已上传媒体的 id**（`uploadMedia` 返回的 `MediaDto.id`，即 `/media/confirm` 响应的 `id`），图片、语音统一传 id |
| `tags` | 选 | array ≤10 | 标签字符串数组（如 `["sight","food"]`），原样存储、响应顶层 `tags` 返回 |

- **不传**：`media`（URL 数组）、`clientId`、`city`、`type`（后端按 mediaIds 查出的 kind 自动推导 photo/voice）
- **行为（后端保证，已实测）**：
  - id 校验：属于当前用户 + 状态 `active` + **未被其他记录占用** → 不满足返回 400（事务回滚无残留）
  - 配额：上传时（`/media/confirm`）已计，create 不重复计
  - 同一 id 只能被一条记录关联（二次使用 400）——**前端删除照片重传后，必须用新的 id 提交**
- ⚠️ **USE_MOCK=true 时**：`uploadMedia` 返回 `mock_xxx` 假 id，create 传它会 400（后端无此行）。**联调记录新建+媒体时必须 USE_MOCK=false**（或上传用 mock 时 create 不传 mediaIds）

## 6. 调整三：编辑记录 `/records/update` — `images` → `mediaIds`

### 6.1 为什么同步调整

| 旧做法 | 问题 |
|---|---|
| 编辑传 `images: ["https://..."]` URL 数组，后端按 storageKey 匹配收养 | 与 create 不一致；URL 改写、云存储迁移后可能匹配失败 |
| 编辑记录前端需保留并重新提交完整的 URL 数组 | 本地缓存了 mediaIds 却不用，绕路一次 |

同步到 `mediaIds` 后：create 与 update 使用同一套 id 关联机制，前端无需再维护两套数据。

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `mediaIds` | 选 | array ≤20 | |已上传媒体的 id（与 `entries/create` 完全一致） |
| `tags` | 选 | array ≤10 | 标签字符串数组（覆盖式：空数组/`null` 清空、不传不动） |

### 6.3 行为规则（覆盖写）

- **传空数组 `[]`**：清空该记录所有图片
- **不传 `mediaIds`**：不动，保留现有图片
- **传有效 id 数组**：替换为该批 id（覆盖写）
- **`tags` 同理覆盖写**：空数组/`null` 清空标签、不传不动；`entries/create` 的 `tags` 新建时写入
- 后端校验：属于当前用户 + 未被其他 entry 占用 → 不满足返回 400
