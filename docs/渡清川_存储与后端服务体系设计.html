渡清川 · 存储与后端服务体系设计

文档类型：后端架构设计　|　日期：2026-07-24　|　角色：Backend Architect　|　对齐栈：NestJS 10 + TypeORM 0.3 + MySQL + JWT
一句话架构：用存储适配器（Strategy 模式）把"文件存哪"和"业务怎么用"解耦——开发期 driver=local 落本地磁盘、通过后端受控路由回读；上线期改 driver=cos 走腾讯云预签名直传。前端上传契约（prepare → upload → confirm）全程不变，所以"本地先跑、将来上云"是配置级切换，不碰业务代码，也不破坏前后端打通。

一、约束对齐（基于你的现状文档）

现状（来自后端现状文档）本设计的处理
MySQL + TypeORM + NestJS 10，全局前缀 /api、版本 v1沿用，不换栈、不换 ORM
JWT Bearer 鉴权，userId 仅从 token 取沿用，强化：任何写操作禁止前端传 userId

二、存储适配器：本地开发如何"真打通"

2.1 为什么必须抽象一层

微信小程序不能直接写服务器磁盘，文件必须经 HTTP 上传。如果开发期让前端直传本地后端、生产期直传 COS，两端上传逻辑不同，契约就碎了。抽象出 StorageDriver 后：

  • prepare：业务侧只拿"一个可上传的 URL + 一个确认令牌"，不关心底层是本地还是 COS；
  • upload：前端统一用 wx.uploadFile 把文件发到 uploadUrl；
  • confirm：上传完成后回注册媒体记录、扣配额。本地和 COS 走同一 confirm，差异只在第一步。
上传契约（前后端恒定）： prepare ──► { uploadUrl, method, headers, fields, mediaId, confirmToken } │ ├─ driver=local : uploadUrl = POST /api/v1/media/local-upload (后端写盘+建记录) └─ driver=cos : uploadUrl = COS 预签名 PUT (前端直传云) │ ▼ confirm ──► { mediaId, confirmToken } ──► 标记 active + 扣配额 + 返回最终媒体 DTO

2.2 本地开发存储方案（具体怎么存）

落盘路径按日期分区，避免单目录海量小文件：{UPLOAD_ROOT}/yyyy/mm/dd/{uuid}.{ext}。示例 ./uploadImgFile/2026/07/24/9f3a...e2.jpg
文件名服务端随机 UUID，**绝不**用客户端原始文件名（防路径穿越、防中文/特殊字符、防覆盖）
回读方式后端 FilesController 提供 GET /api/v1/files/:y/:m/:d/:file，做路径穿越校验 +（生产）所有权/签名校验；开发期可放宽但必须挡 ..
容量隔离UPLOAD_ROOT 放在仓库外（如 ~/dqc-storage），不进 git；.gitignore 忽略
配额落盘成功后 服务端累加 users.usedPhoto / usedVoiceSec，拒绝信任前端自报
// .env（开发）
STORAGE_DRIVER=local
UPLOAD_ROOT=/home/dev/dqc-storage/uploads
FILE_SERVE_PREFIX=/api/v1/files
# 生产切换：STORAGE_DRIVER=cos + COS_SECRET_ID/KEY/BUCKET/REGION

2.3 本地 → COS 迁移路径（零业务改动）

三、数据库设计（现状 + 扩展性）

核心改动：把 media 从"只挂 entry"升级为多态归属实体，一处管理图片/音频及未来所有媒体（头像、封面、攻略图、目的地图）。这是你"组合关系 + 未来扩展"诉求的落点。

3.1 media 表（重构后，MySQL DDL）

CREATE TABLE media (
  id           VARCHAR(36)  PRIMARY KEY,
  owner_type   VARCHAR(24)  NOT NULL COMMENT 'entry|avatar|journey_cover|guide|destination',
  owner_id     VARCHAR(36)  NOT NULL,
  kind         VARCHAR(12)  NOT NULL COMMENT 'image|audio',
  url          VARCHAR(512) NOT NULL,
  thumb_url    VARCHAR(512) NULL,
  mime         VARCHAR(64)  NOT NULL,
  ext          VARCHAR(8)   NULL,
  size_bytes   BIGINT       NOT NULL DEFAULT 0,
  width        INT          NULL,
  height       INT          NULL,
  duration_sec INT          NULL COMMENT '音频时长',
  checksum     VARCHAR(64)  NULL COMMENT 'sha256 去重',
  sort_order   INT          NOT NULL DEFAULT 0,
  status       VARCHAR(12)  NOT NULL DEFAULT 'active' COMMENT 'pending|active|deleted',
  storage_tier VARCHAR(8)   NOT NULL DEFAULT 'hot' COMMENT 'hot|cold',
  driver       VARCHAR(8)   NOT NULL DEFAULT 'local' COMMENT 'local|cos（迁移标记）',
  created_by   VARCHAR(36)  NULL,
  created_at   DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at   DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  deleted_at   DATETIME(3)  NULL,
  INDEX idx_owner    (owner_type, owner_id, deleted_at),
  INDEX idx_checksum (checksum),
  INDEX idx_created  (created_by, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

设计要点

  • 组合关系落地：一条 entry 通过 owner_type='entry' AND owner_id=:entryId 关联 N 张图 + N 条语音，按 sort_order 排序——文字/定位/花费是 entry 自身字段或 1:1 子表，媒体是"一对多附件"，天然支持"图文音组合"。
  • 去重：checksum 可识别相同文件，未来支持"上传一次、多处引用"（如封面复用旅行图）。
  • 软删：deleted_at 与全局约定一致，回收站/审计友好。
  • 驱动标记：driver 字段让本地→COS 迁移可逐条回写，不影响在线。
  • 缩略图：thumb_url 预留，未来音频波形图/图片压缩版各取所需，前端首屏不用拉原图。

3.3 关联与组合关系全景

users 1─* journeys 1─* entries 1─* media (owner_type='entry') journeys 1─* destinations (软删) journeys 1─* checklist_items (软删) 复用同一 media： users 1─* media (owner_type='avatar') journeys 1─1 media (owner_type='journey_cover') guides 1─* media (owner_type='guide') destinations 1─* media (owner_type='destination')

所有"存图/存音"的需求都收敛到 media 一张表，新增一种媒体归属只需加一个 owner_type 枚举值，不动表结构——这就是扩展性。

四、接口设计（聚合 · 效率 · 关联）

4.1 统一媒体上传契约（前后端恒定）

方法路径说明
POST/media/prepare入参 { ownerType, ownerId, kind, mime, sizeBytes }；返回 { mediaId, uploadUrl, method, headers, fields, confirmToken }
POST/media/local-upload仅 local 驱动：接收 wx.uploadFile，写盘 + 建 pending 记录，返回 mediaId
POST/media/confirm入参 { mediaId, confirmToken }；标记 active、扣配额、回最终媒体 DTO
GET/api/v1/files/:y/:m/:d/:file本地回读（穿越校验 + 所有权）

4.2 聚合响应（避免 N+1，前端一次拿全）

GET /journeys/:id/entries 直接内联媒体数组，前端不必为每条 entry 再请求媒体：

// 响应结构（entry 聚合 media）
{
  "id": "entry-uuid",
  "type": "photo",
  "content": "洱海边的清晨",
  "recordedAt": "2026-07-22T08:30:00+08:00",
  "dayIndex": 2,
  "location": { "lat": 25.62, "lng": 100.23, "name": "洱海生态廊道" },
  "media": [                                 // ← 一对多，一次返回
    { "id":"m1", "kind":"image", "url":"/api/v1/files/2026/07/22/a.jpg", "width":4032, "height":3024, "sortOrder":0 },
    { "id":"m2", "kind":"audio", "url":"/api/v1/files/2026/07/22/b.m4a", "durationSec":18, "sortOrder":1 }
  ]
}

实现：Service 层用 TypeORM leftJoinAndSelect('entry.media', 'media')，按 owner_type='entry' 过滤并按 sort_order 排序，由数据库一次取回，杜绝 N+1。

4.3 效率与关联约定

  • 分页：列表接口强制 ?page=&pageSize=，默认 pageSize=20，上限 100，游标优先于 offset（大数据量）。
  • 字段选择：媒体列表用投影只取 id,url,kind,thumbUrl，原图不在列表流里。
  • 统一响应：业务接口裸 JSON；统计沿用 { code,message,data,range }；错误统一 HttpExceptionFilter。
  • 幂等：entry 用 clientId 全局唯一 upsert；媒体用 confirmToken 防重复 confirm。

5.1 存储驱动接口与本地实现

// storage/storage-driver.interface.ts
export interface UploadTargetInput {
  ownerType: string; ownerId: string; kind: 'image'|'audio';
  mime: string; sizeBytes: number;
}
export interface UploadTarget {
  mediaId: string; uploadUrl: string; method: 'POST'|'PUT';
  headers: Record<string,string>; fields: Record<string,string>;
  confirmToken: string;
}
export interface StoredObject { key: string; url: string; }
export interface StorageDriver {
  getUploadTarget(input: UploadTargetInput, mediaId: string, token: string): Promise<UploadTarget>;
  resolveUrl(key: string): string;
  delete(key: string): Promise<void>;
}

// storage/local-storage.driver.ts
@Injectable()
export class LocalStorageDriver implements StorageDriver {
  constructor(@Config() private cfg: ConfigService, private httpAdapter: HttpAdapterHost) {}
  async getUploadTarget(input: UploadTargetInput, mediaId: string, token: string) {
    const base = this.cfg.get('APP_BASE_URL');
    return {
      mediaId,
      uploadUrl: `${base}/api/v1/media/local-upload`,
      method: 'POST',
      headers: {},
      fields: { mediaId, confirmToken: token }, // wx.uploadFile 的 formData
      confirmToken: token,
    };
  }
  resolveUrl(key: string) { // key = 2026/07/22/a.jpg
    return `${this.cfg.get('FILE_SERVE_PREFIX')}/${key}`;
  }
  async delete(key: string) { /* fs.unlink 安全路径校验后删除 */ }
}

5.3 Media Service（prepare/confirm/聚合）

// modules/media/media.service.ts（核心节选）
@Injectable()
export class MediaService {
  constructor(@InjectRepository(Media) private repo: Repository<Media>,
              private drivers: StorageDriverFactory,
              private users: UserService, @Config() private cfg: ConfigService) {}

  async prepare(dto: PrepareDto, userId: string) {
    // 1) 服务端配额预检（边界先拦，省一次上传）
    await this.users.assertQuota(userId, dto.kind, dto.sizeBytes);
    const mediaId = randomUUID();
    const token = sign({ mediaId, userId }, this.cfg.get('JWT_SECRET'), { expiresIn: '10m' });
    const driver = this.drivers.get(); // local | cos
    const target = await driver.getUploadTarget(dto, mediaId, token);
    // 写 pending 记录，confirm 时转 active
    await this.repo.save({ id: mediaId, ownerType: dto.ownerType, ownerId: dto.ownerId,
      kind: dto.kind, mime: dto.mime, sizeBytes: dto.sizeBytes, status: 'pending',
      driver: this.cfg.get('STORAGE_DRIVER'), createdBy: userId, url: '' });
    return target;
  }

  async confirm(mediaId: string, token: string, userId: string) {
    const payload = verify(token, this.cfg.get('JWT_SECRET')); // 防伪造
    if (payload.mediaId !== mediaId) throw new BadRequestException('token mismatch');
    const m = await this.repo.findOne({ where: { id: mediaId } });
    if (!m || m.status !== 'pending') throw new NotFoundException();
    m.status = 'active';
    await this.repo.save(m);
    await this.users.incrUsed(userId, m.kind, m.sizeBytes); // 服务端扣配额
    return this.toDto(m);
  }
}

5.4 本地回读控制器（防穿越 + 所有权）

// modules/media/files.controller.ts
@Controller('files')
export class FilesController {
  @Get(':y/:m/:d/:file')
  @UseGuards(JwtAuthGuard)               // 生产必须登录；dev 可放宽到 DevGuard
  async serve(@Param('y') y, @Param('m') m, @Param('d') d, @Param('file') file, @Req() req) {
    // 1) 绝对防穿越：拼接后用 path.normalize 再校验仍在 UPLOAD_ROOT 内
    const safe = path.normalize(path.join(y,m,d,file));
    if (safe.includes('..') || safe !== path.join(y,m,d,file)) throw new ForbiddenException();
    const full = path.join(this.cfg.get('UPLOAD_ROOT'), safe);
    if (!full.startsWith(this.cfg.get('UPLOAD_ROOT'))) throw new ForbiddenException();
    // 2) 生产：校验该文件 owner 属于当前用户（读 media 表比对 createdBy）
    return res.sendFile(full);
  }
}

5.5 统一响应与异常（沿用现状约定）

// common/filters/http-exception.filter.ts（增强：生产剥栈）
@Catch(HttpException)
export class HttpExceptionFilter implements ExceptionFilter {
  catch(ex: HttpException, host: ArgumentsHost) {
    const res = host.switchToHttp().getResponse();
    const isProd = process.env.NODE_ENV === 'production';
    const status = ex.getStatus();
    const body = ex.getResponse() as any;
    res.status(status).json({
      code: body?.code ?? status,
      message: body?.message ?? ex.message,
      timestamp: new Date().toISOString(),
      path: host.switchToHttp().getRequest().url,
      ...(isProd ? {} : { stack: ex.stack }), // 生产不吐栈
    });
  }
}

六、安全设计（调试接口 + 数据安全）

6.1 调试 / 生产隔离

风险点措施
开发登录 dev_openid_demoif (isProd) throw ForbiddenException('dev login disabled')；生产环境该分支不可达
Swagger 暴露if (!isProd) setupSwagger()；或生产挂 admin 鉴权后开启
详细错误/堆栈HttpExceptionFilter 生产环境剥离 stack（见 5.5）
CORSdev 允许前端来源（env CORS_ORIGIN）；prod 白名单严格，禁止 *
调试路由所有 /dev-* 路由统一 DevGuard：生产直接 403

6.2 上传安全

  • MIME / 大小白名单：图片仅 image/jpeg,png,webp；音频仅 audio/m4a,mp3,aac；图片 ≤10MB、音频 ≤30MB（和配额双重约束）。
  • 随机文件名：UUID + 真实扩展名，绝不用客户端文件名，从根上消除路径穿越。
  • checksum 去重：相同 sha256 不重复落盘，省空间也防滥用上传。
  • 配额服务端强制：prepare 阶段预检、confirm 阶段实扣，前端自报一律无效。
  • 限流：@nestjs/throttler 对 /auth/* 与 /media/* 限流，防爆破/刷量。
  • 未来病毒扫描：在 confirm 前留 hook（如 ClamAV / 云扫描），本地 dev 跳过。

6.3 数据安全

  • userId 仅取 JWT：所有写操作以 req.user.id 为准，DTO 含 userId 字段直接白名单剔除（现状 ValidationPipe whitelist 已支持）。
  • PII 加密：users.phone AES-256 落库，响应脱敏；locations.encryptedPoly 位置加密（PIPL 预留）。
  • 媒体 URL 签名：生产 COS URL 带过期签名；本地回读走 6.4 所有权校验。
  • 参数化查询：TypeORM 全程参数化，杜绝 SQL 注入（禁止字符串拼接 SQL）。
  • PIPL 导出：沿用 GET /me/export，提供数据可携与删除。
