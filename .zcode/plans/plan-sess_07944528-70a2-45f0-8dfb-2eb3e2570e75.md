# 途记后端止血修复计划

范围：资金与账号安全 → 数据库迁移链 → 配额与数据一致性 → 文件访问模型（已确认公开只读）。性能重构、架构调整、工程化建设列入后续迭代，不在本次范围。

## 阶段 1：资金与账号安全（约 0.5-1 天）

1. **堵住 membership mock 支付裸奔**（`src/modules/membership/membership.controller.ts:59`、`membership.service.ts:222`）
   - `POST /membership/orders/:orderNo/pay` 挂 `DevOnlyGuard`，与 payment 模块 `completeMockPayment` 同规格；
   - `payOrder` 增加与 payment 一致的两道闸：`DEV_PAY_NOTIFY_SECRET` 必须匹配、微信商户已配置（`WX_MCH_ID` 存在）时拒绝 mock 支付；`mockPayToken` 校验或删除该摆设字段；
   - 同步更新 `src/scripts/e2e-local.ts` 的支付流程携带 secret。
2. **密钥 fail-fast**（`src/modules/auth/jwt.strategy.ts:12`、`auth.module.ts:21`）
   - 删除 `|| 'tuji_dev_secret'` 兜底，`JWT_SECRET` 缺失时启动即抛错；`DEV_PAY_NOTIFY_SECRET` 删除 `'tuji_dev_pay'` 默认值，未配置则 dev-complete 直接拒绝；
   - `.env.example` 同步更新说明。
3. **统一 dev 判据 + 显式调试开关**：新增 `src/common/env.ts` 作为 `isProd()/isDevEnabled()` 单一出口，收敛 dev-only.guard、wechat.service、http-exception.filter、main.ts、database.module 五处独立判断；DevOnlyGuard 判据改为"非 production **且** `ENABLE_DEV_PAY=true`"双条件。
4. **mock 登录收敛**（`src/infrastructure/wechat/wechat.service.ts:42`）：code 当 openid 的行为仅在显式 `ENABLE_MOCK_LOGIN=true` 下生效；删除 `.env.example` 与代码中提交的真实样例 openid。
5. **`GET /me` 脱敏**（`src/modules/user/user.service.ts:74`）：`toLegacyUserResponse` 从 `...u` 展开改为白名单挑拣——去掉 `openid/unionid/phone` 明文（phone 用现有 phoneMasked 逻辑），保留 plan/配额等前端在用字段；登录响应 `auth.service.ts:24` 同步收口。改动后用 e2e 验证前端依赖字段未缺失。

## 阶段 2：数据库迁移链补齐（约 1 天，生产可部署性的关键）

1. **删除根目录 `migrations/member-schema.sql`**（snake_case 错误版，防止误执行）。
2. **新增一个 schema 对齐迁移** `AlignSchemaWithEntities`，以实体定义为准补齐：
   - 缺失的 8 张表：checklist_items、drafts、invite_codes、invite_records、shares、user_identities、travel_identity_dict、user_stats_snapshots（含 share_events 的最终形态确认）；
   - media 多态结构（ownerType/ownerId + 查询索引）；
   - users 缺失列（unionid/role/status/deletedAt/memberExpireAt/配额四字段等）；
   - member_plans/orders 会员相关表与列（吸收 `src/migrations/member-schema.sql` 的正确内容）；
   - 统一 collation 为库默认（消除 unicode_ci/0900_ai_ci 分裂）；
   - `orders.transactionId` 唯一索引。
3. **修复存量迁移质量问题**：`EntryMultiExpense.ts` 去掉 `.catch(() => undefined)` 吞错；核实 `R1R5Align` 对 share_events 的 DROP/重建与新对齐迁移衔接自洽。
4. **编写空库验证脚本** `src/scripts/verify-migrations.ts`：空库跑迁移 → 与 dev synchronize 的库做 information_schema 结构 diff，以差异为空作为验收标准（该脚本长期保留为回归资产）。
5. dev 侧暂保持 `synchronize=true`（开发效率优先），migration-only 化列入后续。

## 阶段 3：配额与数据一致性（约 1 天）

1. **配额原子化**（`src/modules/quota/quota.service.ts`）
   - `assertWithin + addUsage` 合并为原子 `tryConsume`：`UPDATE users SET usedPhoto = usedPhoto + :n WHERE id = :id AND usedPhoto + :n <= quotaPhoto`，affected=0 时区分用户不存在/超配额抛对应异常；支持传入 EntityManager 纳入外部事务；
   - 改造调用点：`media.service.ts` confirm、`recording.service.ts` upsertChildren/sync 传入事务 manager，消除"事务回滚但配额已扣"。
2. **删除路径释放配额**：`removeRecord`/`removeEntries`/`patchRecord` 移除媒体时在事务内按 kind 返还 usedPhoto/usedVoiceSec。
3. **删除级联清理**（`recording.service.ts:1190`）：删除记录/条目改为事务内同步清理 expenses、media 行，事务外调用 `driver.delete()` 清理物理文件（失败仅告警）；journey 级联删除 entry 的路径同样补齐清理逻辑。
4. **journey 写路径事务化**（`journey.service.ts`）：create/updateStatus/putPlan/patchPlan/createPlanPlace/deletePlanPlace 包 `dataSource.transaction`；`seedPlanPlaceEntries`/`prunePlanPlaceEntries` 去掉吞错，失败即回滚。
5. **读路径去掉写库副作用**：`toListItem` 不再触发 `ensurePlan` 写库，ensurePlan 仅保留在 journey 创建/状态变更等写路径；存量缺 plan 数据用一次性补偿脚本补齐。

## 阶段 4：文件访问模型与存储防护（约 0.5 天，已确认公开只读）

1. `src/modules/media/files.controller.ts` 去掉 `JwtAuthGuard` 与所有权校验，保留路径穿越校验（文件名为 UUID 不可枚举）；代码内留 TODO 指向后续签名 URL 升级。
2. **COS 驱动启动护栏**（`storage-driver.factory.ts`）：`STORAGE_DRIVER=cos` 时启动直接失败并提示驱动未完成（无签名直传、delete 为 no-op），防止误切换导致上传链路瘫痪。
3. 阶段 3 的物理文件删除接入 local driver 现有 `delete()`。
