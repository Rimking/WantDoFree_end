# 渡清川 · 接口聚合与缓存策略盘点

> 日期：2026-07-24（修订：HTTP 方法约定 + 单查保留 + 响应模块化）  
> 依据：当前前端 `src/api/*`、`src/stores/*`、主要页面进页拉取逻辑  
> 服务前缀：`/api/v1`  
> 目的：给前后端对齐「聚合 / 单查 / 缓存 / 方法 / 响应结构」

---

## 0. 结论先看

### 0.1 HTTP 方法约定（重要）

| 场景 | 方法 | 说明 |
|------|------|------|
| **无业务参数**的获取 | **GET** | 如 `GET /me`、`GET /me/quota`、`GET /user/identities` |
| **有参数**的获取（筛选、id、分页、range…） | **POST** | 参数放 **JSON body**，不要靠 query string |
| **写入 / 更新 / 删除 / 状态变更** | **POST** | 统一 POST；逐步收敛现有 PUT/PATCH/DELETE |
| 路径上的资源 id | 可保留在 path | 如 `/journeys/:id/detail`；其余筛选条件进 body |

> **一句话**：没参用 GET；只要要传参（含查询条件），获取和设置都用 POST。

### 0.2 建议优先聚合（P0）

| 场景 | 现状 | 建议（新契约） |
|------|------|----------------|
| **旅程详情页** | 4 连发 GET | **`POST /journeys/detail`** body:`{ journeyId, include? }` |
| **统计首页** | 6 连发 GET + query | **`POST /stats/dashboard`** body:`{ rangeType, start?, end?, journeyId? }` |
| **手帐预览** | guide + entries + plan | 复用 detail 的 `include:["guide",…]`，或 `POST /journeys/guideView` |

响应必须 **按模块嵌套对象**（`journey` / `plan` / `entries` / `expense`…），禁止一堆平铺字段。

### 0.3 单查保留（备后续单独查询）

聚合 **不删除** 下列单资源接口；二级页、局部刷新、写后回读继续用它们（方法按 §0.1 迁移）。详见 **§2**。

### 0.4 缓存策略

| 类型 | 策略 |
|------|------|
| 统计 / 计划 / 花费 / 时间线 / 旅程业务 | **禁止本地当真源**；进页打服务端 |
| token、onboarding、最近选点、outbox | 可本地 |
| 个人资料 / 配额 | 登录后短缓存；资料页再刷 |
| `statsLocal` 静默兜底 | 正式环境关掉 |

## 1. HTTP 方法：现状 → 目标对照

### 1.1 可继续用 GET（无参获取）

| 现路径 | 说明 |
|--------|------|
| `GET /me` | 当前登录用户摘要 |
| `GET /me/quota` | 配额（无 year 等参数时） |
| `GET /user/profile` | 完整资料（无参） |

| `GET /user/regions` | 地区字典 |
| `GET /drafts` | 草稿列表（若永远无筛选；有筛选则改 POST） |
| `GET /files/...` | 本地文件下载（path 即定位，特殊） |

### 1.2 建议改为 POST（有参获取 / 所有写入）

| 现方法 | 现路径 | 问题 | 目标 |
|--------|--------|------|------|
| GET | `/journeys?status=` | 有筛选 | `POST /journeys/list` body |
| GET | `/journeys/:id` | 有 id（可 path 或 body） | 可保留 GET 无多余参；或统一 `POST /journeys/get` `{id}` |
| GET | `/journeys/:id/plan` | 有 id | `POST /journeys/plan/get` `{journeyId}` |
| GET | `/journeys/:id/entries` | 有 id | `POST /journeys/entries/list` `{journeyId}` |
| GET | `/journeys/:id/expense-summary` | 有 id | `POST /journeys/expense/summary` `{journeyId}` |
| GET | `/journeys/:id/guide` | 有 id | `POST /journeys/guide/get` `{journeyId}` |
| GET | `/journeys/:id/guide/check` | 有 id | 并入 guide/get 或 `POST .../guide/check` |
| GET | `/me/budget?year=` | 有 year | `POST /me/budget/get` `{year}` |
| GET | `/me/expense-summary?year=` | 有 year | `POST /me/expense/summary` `{year}` |
| GET | `/stats/*?rangeType=…` | 一律有参 | 全部 `POST /stats/...` body |
| GET | `/pois/nearby?lat&lng` | 有参 | `POST /pois/nearby` |
| GET | `/pois/search?keyword=` | 有参 | `POST /pois/search` |
| GET | `/pois/reverse-geocode?…` | 有参 | `POST /pois/reverseGeocode` |
| PUT/PATCH | `/journeys/:id/plan` 等 | 写入 | 统一 `POST .../save` / `.../patch` |
| DELETE | `/journeys/:id`、`entries/:id` | 删除 | `POST .../delete` `{id}` |
| PATCH | `/me`、`/user/profile`、`/me/budget` | 写入 | `POST .../update` |

## 2. 单独保留的接口（聚合之外，备后续单查）

> 原则：**页面首屏用聚合；局部刷新 / 二级页 / 写后回读用单查。**  
> 单查接口与聚合里的模块对象 **字段同构**，避免两套 DTO。

### 2.1 旅程域

| 目标接口 | 方法 | Body 要点 | 何时单查 |
|----------|------|-----------|----------|
| `/journeys/list` | POST | `{ status?, page?, pageSize? }` | 首页列表、筛选 Tab |
| `/journeys/get` | POST | `{ id }` | 只刷新标题/封面/状态 |
| `/journeys/create` | POST | 创建字段 | 新建 |
| `/journeys/update` | POST | `{ id, ...patch }` | 编辑页保存 |
| `/journeys/delete` | POST | `{ id }` | 删除 |
| `/journeys/status` | POST | `{ id, target }` | 开始/结束旅程 |
| `/journeys/detail` | POST | `{ journeyId, include? }` | **详情首屏聚合（P0）** |

### 2.2 计划域（单查保留）

| 目标接口 | 方法 | Body | 何时单查 |

### 2.3 记录域（单查保留）

| 目标接口 | 方法 | Body | 何时单查 |
|----------|------|------|----------|

### 2.4 花费域（单查保留）

| 目标接口 | 方法 | Body | 何时单查 |
|----------|------|------|----------|
| `/journeys/expense/summary` | POST | `{ journeyId }` | 旅程记账页 |
| `/me/expense/summary` | POST | `{ year }` | 旧记账总览（可 deprecate） |

### 2.5 手帐域（单查保留）

| 目标接口 | 方法 | Body | 何时单查 |
|----------|------|------|----------|
| `/journeys/guide/get` | POST | `{ journeyId }` | 只读手帐 |
| `/journeys/guide/create` | POST | `{ journeyId, template? }` | 生成 |
| `/journeys/guide/favorite` | POST | `{ journeyId, isFavorited? }` | 收藏 |

建议 `guide/get` 响应内带 `exists`、`canGenerate`、`reason`，去掉单独 check。

### 2.6 统计域

| 目标接口 | 方法 | Body | 角色 |
|----------|------|------|------|
| `/stats/dashboard` | POST | range 筛选 | **首页聚合（P0）** |
| `/stats/overview` | POST | 同左 | 单查保留 |
| `/stats/expenses` | POST | + 可选 journeyId | 消费二级页 |
| `/stats/plans` | POST | | 计划二级页 |

| `/stats/content` | POST | | 内容块刷新 |
| `/stats/storage` | GET 或 POST | 无参可用 GET | 存储页；dashboard 已含则可少打 |

### 2.7 用户 / 媒体 / POI（单查保留）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/auth/wechat-login` | POST | 登录 |
| `/me`、`/me/quota` | GET | 无参 |
| `/me/budget/get`、`/me/budget/update` | POST | 有 year / amount |
| `/user/profile` GET；`/user/profile/update` POST | | 资料 |
| `/user/identities`、`/user/regions` | GET | 字典无参 |
| `/user/nickname/check` | POST | 有 nickname |
| `/media/prepare`、`confirm` | POST | 上传三步保留 |
| `/pois/nearby|search|reverseGeocode` | POST | 有参 |
| `/drafts` | GET 或 POST | 有筛选则 POST |

## 3. 响应结构：按模块嵌套（禁止平铺大杂烩）

### 3.1 问题（现状）

- 多接口字段平铺：`totalExpense` / `expenseTotal` / `totalCent` 混用  
- 同一资源多别名：`cover` / `coverUrl`，`nick` / `nickname`  
- 列表项把计划、花费、计数摊在根上，没有对象边界  
- 聚合若再平铺，前端更难维护

### 3.2 约定

1. **一个业务模块 = 一个对象**（或该对象的数组）  
2. 聚合接口 = 多个模块对象的容器，**不要**把子模块字段抬到根上  
3. 单查接口返回的模块对象，与聚合里同名对象 **字段完全一致**  
4. 废弃别名：新契约只保留一套（如只用 `coverUrl`、`nickname`、`amountCent`）  
5. 前端用不到的字段：聚合里可不返回；单查可按 `fields`/`include` 裁剪（可选）

### 3.3 模块对象字典（建议后端统一）

| 模块 key | 含义 | 典型字段（精简） |
|----------|------|------------------|
| `user` | 用户摘要 | `id, nickname, avatarUrl, memberLevel` |
| `quota` | 配额 | `photo{used,limit,remaining}, voiceSec{…}` |
| `journey` | 旅程本体 | `id, title, origin, destination, coverUrl, startDate, endDate, status, themeTags, companions, budgetAmount` |
| `journeyStats` | 旅程计数摘要 | `placeCount, recordCount, expenseTotalCent`（列表用） |
| `plan` | 计划 | `places[], checks[], budgetEstimate` |
| `entries` | 时间线 | `Entry[]`（见下） |
| `expense` | 花费汇总 | `totalCent, count, byCategory[], byDay[]` |
| `guide` | 手帐 | `exists, id, title, coverUrl, highlights[], …` |
| `overview` / `plans` / `journeys` / `content` / `storage` / `expenses` | 统计子模块 | 与 `src/types/stats.ts` 对齐，但各自成对象 |

**Entry 建议结构（模块内再嵌套）：**

```json
{
  "id": "...",
  "clientId": "...",
  "type": "photo",
  "content": "...",
  "dayIndex": 1,
  "createdAt": "...",
  "location": { "lat": 0, "lng": 0, "name": "断桥" },
  "expense": { "amountCent": 18000, "category": "food", "currency": "CNY", "note": "" },
  "media": [ { "id": "...", "kind": "image", "url": "...", "sortOrder": 0 } ],
  "audio": { "url": "...", "durationSec": 12 }
}
```

不要再并行返回平铺的 `images[]` + `audioUrl` + `voice`（兼容期可放 `legacy` 对象，正式去掉）。

### 3.4 聚合响应示例

#### `POST /journeys/detail`

**Request**

```json
{
  "journeyId": "uuid",
  "include": ["entries", "plan", "expense", "guide"]
}
```

`include` 默认 `["entries","plan","expense"]`。

**Response `data`**

```json
{
  "journey": { },
  "journeyStats": {
    "placeCount": 4,
    "recordCount": 12,
    "expenseTotalCent": 108700
  },
  "plan": {
    "places": [],
    "checks": [],
    "budgetEstimate": 0
  },
  "entries": [],
  "expense": {
    "totalCent": 108700,
    "count": 8,
    "byCategory": [],
    "byDay": []
  },
  "guide": null
}
```

根上 **只有模块 key**，没有散落的 `title`、`totalCent`。

#### `POST /stats/dashboard`

**Request**

```json
{
  "rangeType": "year",
  "start": null,
  "end": null,
  "journeyId": null
}
```

**Response `data`**

```json
{
  "range": { "type": "year", "start": "2026-01-01", "end": "2026-12-31" },
  "overview": { },
  "plans": { },
  "journeys": { },
  "content": { },
  "storage": { },
  "expenses": { }
}
```

首页若只要预览，可用精简字段；**对象壳仍在**，二级页 `POST /stats/expenses` 返回完整 `expenses` 同构对象。

### 3.5 列表项也要模块化（避免无用字段炸裂）

**差（平铺）：**

```json
{
  "id": "...",
  "title": "...",
  "placeCount": 4,
  "expenseTotal": 108700,
  "places": [],
  "checks": [],
  "entries": []
}
```

列表不需要把 plan/entries 整包带回。

**好：**

```json
{
  "journey": { "id": "...", "title": "...", "coverUrl": "...", "status": "ongoing", "...": "..." },
  "journeyStats": { "placeCount": 4, "recordCount": 12, "expenseTotalCent": 108700 },
  "planProgress": { "checkDone": 3, "checkTotal": 8, "pct": 38 }
}
```

未用到的大字段（完整 places、entries、guide.highlights）**列表禁止返回**。

## 4. 按页面：连发问题与改法

### 4.1 旅程详情（应聚合）

现状：`journey` + `entries` + `expense-summary` + `plan` → 4 次。  
目标：一次 `POST /journeys/detail`。  
写操作仍走 §2 单查 POST。

### 4.2 统计首页（应聚合）

现状：6 个 `/stats/*`。  
目标：一次 `POST /stats/dashboard`。  
点进「消费/计划/旅程/存储」再用对应单查 POST。

### 4.3 合理保持多次请求的场景

| 场景 | 说明 |
|------|------|
| 先 detail 再用户点「记一笔」 | sync 单查 |
| 上传多图 | prepare→upload→confirm 循环（必要） |
| 选点页 | POI 按需 POST |
| 统计改筛选后进二级页 | dashboard 与 expenses 分开 |

## 5. 本地缓存盘点

### 5.1 不应当真源

| Key | 建议 |
|-----|------|
| `journeys` / `plans` / `recordings` | 进页远端覆盖；勿跨会话当真 |
| `guideCache` / `guideFavorites` | 信接口 |
| `yearBudgetCents` | 信 `/me/budget` |
| `statsLocal` 静默兜底 | 正式关闭 |

### 5.2 可保留

| Key | 理由 |
|-----|------|
| `token` | 登录 |
| `user` 摘要 | 短缓存 |
| `onboardingDone` / `authAsked` | 流程标记 |
| `currentJourneyId` | UI 态 |
| `recentLocations` | 体验 |
| `outbox` | 仅明确要离线时 |
| `drafts` | 允许本地 + 对齐接口 |

## 8. 给后端的最小行动

1. 文档化并执行：**无参 GET，有参一律 POST（读也是）**  
2. 先实现 `POST /journeys/detail`、`POST /stats/dashboard`，响应 **按模块对象嵌套**  
3. 保留 §2 单查接口并与聚合模块同构，供二级页与局部刷新  
4. 列表与详情砍掉用不到的大字段；别名字段收敛  

## 9. 给前端的最小行动

1. 聚合上线后改接线；查询入参改 body  
2. 解析改为读 `data.journey` / `data.plan` 等模块  
3. 统计失败提示，不静默 `statsLocal`  
4. plan/recordings 停止当跨会话真源
