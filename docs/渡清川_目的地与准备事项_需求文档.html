1. 概述

1.1 现状问题

  • 目的地：当前仅用一个弹窗输入「地点名称」，无法补充地址、分类、备注、图片，也没有编辑/删除入口。
  • 准备事项：清单为静态数据，用户无法新增、删除、排序或自定义提醒。
  • 记录：进行中旅程的时间轴内容只读，文字、图片、语音、消费标签均不可修改。

1.2 目标

  • 提供完整的目的地新增/编辑/删除/排序能力。
  • 让「出发前准备」成为可由用户自定义的动态清单。
  • 让时间轴中的单条记录可编辑、可删除。

1.3 范围

模块本期做本期不做
目的地名称、地图位置、分类、备注、图片、必去开关、关联日期、排序POI 自动补全、路线智能规划
准备事项增删改、排序、勾选、默认状态、按旅程存储系统级模板库、定时推送提醒
记录编辑时间、文字、图片、语音、地点标签、消费标签的修改与删除视频、多人协作编辑

1.4 依赖

沿用现有用户鉴权（JWT / 微信登录 openid），所有接口需校验当前用户是否为旅程创建者或同行人。

2. 模块一：目的地管理

2.1 字段清单

字段类型必填说明前后端
idUUID / Int后端生成主键后端
journeyIdFK是所属旅程后端
namestring是地点名称，1-30 字两端
latitudedecimal否纬度，范围 -90~90两端
longitudedecimal否经度，范围 -180~180两端
addressstring否地址描述，0-100 字两端
categoryenum否，默认 OTHERSIGHT / FOOD / STAY / SHOPPING / OTHER两端
notestring否备注，0-120 字两端
imagesstring[]否COS URL 数组，最多 9 张两端
isMustboolean否，默认 false是否标记为必去两端
dayIndexint?否安排到第几天（null 表示未安排）两端
sortOrderint是同 journey 内排序，默认递增后端

2.2 页面与交互

页面入口交互说明
目的地列表旅程详情 / 计划页按 sortOrder 展示；点击菜单或长按弹出 Action Sheet；标题「+添加」进入新增页。
新增/编辑目的地列表添加 / Action Sheet 编辑表单输入；地图选点返回 lat/lng/address；分类 chips 单选；图片支持相册/拍照，最多 9 张。
删除确认Action Sheet / 编辑页底部二次确认弹窗，确认后软删除。
排序编辑态拖拽（二期可做）本期先支持通过「安排到第 X 天」调整分组；组内按创建时间排序。

2.3 校验规则

  • name 必填，1-30 字符，去除首尾空格。
  • latitude/longitude 要么同时存在，要么同时为空。
  • images 最多 9 张，每张 ≤ 5MB，仅允许 jpg/png。
  • 同一 journey 下 name 不能重复（软删除除外）。

2.4 数据模型（Prisma 增量）

model Destination {
  id          String    @id @default(uuid())
  journeyId   String
  name        String    @db.VarChar(60)
  latitude    Decimal?  @db.Decimal(10, 8)
  longitude   Decimal?  @db.Decimal(11, 8)
  address     String?   @db.VarChar(200)
  category    DestinationCategory @default(OTHER)
  note        String?   @db.VarChar(240)
  images      String[]  @default([])
  isMust      Boolean   @default(false)
  dayIndex    Int?
  sortOrder   Int       @default(0)
  createdAt   DateTime  @default(now())
  updatedAt   DateTime  @updatedAt
  deletedAt   DateTime?

  journey     Journey   @relation(fields: [journeyId], references: [id])
  @@index([journeyId, deletedAt])
}

enum DestinationCategory { SIGHT FOOD STAY SHOPPING OTHER }

2.5 接口定义

GET/api/journeys/:journeyId/destinations

获取某旅程下所有未删除的目的地，按 sortOrder 升序。

响应：{ data: Destination[] }

POST/api/journeys/:journeyId/destinations

新增目的地。body 字段同 2.1（除 id/sortOrder）。

响应：{ data: Destination }

PATCH/api/destinations/:destinationId

部分更新。支持更新 name、lat/lng/address、category、note、images、isMust、dayIndex。

响应：{ data: Destination }

DELETE/api/destinations/:destinationId

软删除，设置 deletedAt = now()。

响应：204 No Content

PATCH/api/journeys/:journeyId/destinations/reorder

批量更新排序。body: { items: [{ id, sortOrder }] }

响应：204 No Content

3. 模块二：准备事项管理

3.1 字段清单

字段类型必填说明前后端
idUUID / Int后端生成主键后端
journeyIdFK是所属旅程后端
titlestring是事项名称，1-30 字两端
isDefaultCheckedboolean否，默认 false新建时是否默认勾选两端
remindBeforeDaysint?否出发前 N 天提醒，null 表示不提醒两端
sortOrderint是排序后端

3.2 页面与交互

页面入口交互说明
清单查看态旅程详情页「出发前准备」区块 / 独立页面显示所有事项，点击 checkbox 可切换完成状态；标题右侧「编辑」进入编辑态。
清单编辑态查看态点击「编辑」每条事项左侧出现拖拽柄与删除按钮；底部「添加事项」；顶部「完成」保存并退出。
添加/编辑事项编辑态「添加」/ 点击某事项输入名称、选择提醒时间、设置默认勾选。

3.3 校验规则

  • title 必填，1-30 字符。
  • remindBeforeDays 为 null 或 1~365 的整数。
  • 同一 journey 下 title 不能重复（软删除除外）。

4. 模块三：记录编辑

4.1 字段清单

字段类型必填说明前后端
idUUID / Int后端生成主键后端
journeyIdFK是所属旅程后端
dayIndexint是第几天两端
recordedAtDateTime是记录发生时间（可编辑）两端
contentstring否文本内容，0-500 字两端
imagesstring[]否图片 URL，最多 9 张两端
audioUrlstring?否语音 URL两端
audioDurationint?否语音时长（秒）两端
locationTagobject?否{ name, lat?, lng? }两端
expenseobject?否{ category, amount }，category 来自字典两端

4.2 页面与交互

页面入口交互说明
时间轴进行中 / 已完成旅程详情按天分组、按时间排序；每条记录右上角「更多」按钮。
记录操作菜单点击「更多」选项：编辑这条记录、更改时间、删除记录。
编辑记录菜单「编辑」可修改时间、文字、图片、语音、地点标签、消费标签；底部提供删除入口。

4.3 校验规则

  • recordedAt 必须在旅程日期范围内（可放宽到前后 1 天）。
  • content 0-500 字；图片、语音、文字至少有一项不为空。
  • images 最多 9 张，单张 ≤ 5MB。
  • audioDuration ≤ 300 秒（5 分钟）。
  • expense.amount 0~999,999，保留两位小数。

4.4 数据模型（Prisma 增量）

model RecordEntry {
  id              String    @id @default(uuid())
  journeyId       String
  dayIndex        Int       @default(1)
  recordedAt      DateTime
  content         String?   @db.VarChar(1000)
  images          String[]  @default([])
  audioUrl        String?
  audioDuration   Int?
  locationName    String?   @db.VarChar(60)
  locationLat     Decimal?  @db.Decimal(10, 8)
  locationLng     Decimal?  @db.Decimal(11, 8)
  expenseCategory String?
  expenseAmount   Decimal?  @db.Decimal(12, 2)
  createdAt       DateTime  @default(now())
  updatedAt       DateTime  @updatedAt

  journey         Journey   @relation(fields: [journeyId], references: [id])
  @@index([journeyId, dayIndex, recordedAt])
}

4.5 接口定义

GET/api/journeys/:journeyId/records

查询参数：?dayIndex=1。返回当天记录，按 recordedAt 升序。

PATCH/api/records/:recordId

部分更新记录的任意字段。

响应：{ data: RecordEntry }

PATCH/api/records/:recordId/time

仅修改记录时间。body: { recordedAt: ISOString, dayIndex?: number }

DELETE/api/records/:recordId

物理删除（或软删除，按团队规范）。

5. 通用规范

5.1 错误码

错误码HTTP触发场景前端提示
40001400名称/标题为空或超长「请输入 1-30 字的名称」
40002400坐标格式非法「地图选点异常，请重新选择」
40003400图片数量/大小超限「图片最多 9 张，单张不超过 5MB」
40004400记录内容为空（无文字/图片/语音）「请至少上传一张图片、一段语音或一段文字」
40901409同名目的地/事项已存在「该名称已存在」
40301403非旅程成员操作「你没有权限操作该旅程」
40401404资源不存在或已删除「内容已不存在」

5.2 权限

  • 所有接口校验 JWT，并确认当前用户属于该 journey（创建者或同行人）。
  • 只有创建者可删除目的地/准备事项；同行人可查看和编辑记录（本期不做细粒度权限，统一视为可编辑）。

6. 验收标准

目的地管理
能新增带分类/备注/图片/地图位置的目的地；能编辑并保存；删除后有二次确认；列表无同名重复项。
准备事项
能进入编辑态新增/删除/排序/勾选事项；退出编辑态后状态持久化；默认勾选逻辑正确。
记录编辑
时间轴记录可进入编辑页修改文字、图片、语音、地点、消费；保存后时间轴实时刷新；删除需确认。
权限与异常
非旅程成员无法调用接口；所有字段越界/空值有明确错误提示；网络异常有重试/提示。
