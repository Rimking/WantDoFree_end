## 1. 新建预定点：`POST /dream/v1/journeys/plan/place/create`

### 1.1 请求体

```json
{
  "journeyId": "9e8d9327-...",
  "name": "武侯祠",
  "note": "逛完去吃火锅",
  "recordedAt": "2026-08-18 11:49:00",
  "lat": 30.646,
  "lng": 104.048,
  "coverUrl": "https://example.com/cover.jpg",
  "mediaIds": ["c4e86a00-...", "c4e86a00-..."],
  "tags": ["sight", "must"]
}
```

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `journeyId` | 是 | string | 旅程 id |
| `name` | 是 | string ≤128 | 地点名称（合并了旧 locationName） |
| `note` | 否 | string | 备注 |
| `recordedAt` | 否 | string | 关联日期+预计时间，格式 `YYYY-MM-DD HH:mm:ss` |
| `lat` / `lng` | 否 | number | 经纬度 |
| `coverUrl` | 否 | string | 封面 URL |
| `mediaIds` | 否 | string[] ≤20 | 已上传媒体 id（与 entries/create 一致） |
| `tags` | 否 | string[] ≤10 | 标签：合并 category + intent，如 `["sight","must"]` |

**不再接受的字段**（传了会被忽略）：

| 字段 | 替代 |
|---|---|
| `clientId` | 服务端生成 |
| `category` | 合并到 `tags`，如 `"SIGHT"` → `"sight"` |
| `intent` | 合并到 `tags`，如 `"must"` → `"must"` |
| `locationName` / `address` | 用 `name` |
| `images` | 用 `mediaIds` |
| `cover` | 统一用 `coverUrl` |
| `latitude` / `longitude` | 统一用 `lat` / `lng` |
| `dayIndex` | 从 `recordedAt` + 旅程 startDate 自动派生 |
| `visitTime` | 统一用 `recordedAt` |

### 1.2 响应结构

```json
{
  "places": [
    {
      "id": "p_mt1l0bjy9ca6",
      "clientId": "p_mt1l0bjy9ca6",
      "name": "武侯祠",
      "note": "逛完去吃火锅",
      "coverUrl": "https://example.com/cover.jpg",
      "cover": "https://example.com/cover.jpg",
      "lat": 30.646,
      "lng": 104.048,
      "latitude": 30.646,
      "longitude": 104.048,
      "locationName": null,
      "category": null,
      "dayIndex": 1,
      "recordedAt": "2026-08-18 11:49:00",
      "intent": "planned",
      "images": ["https://example.com/cover.jpg"],
      "sortOrder": 0,
      "tags": ["sight", "must"],
      "mediaIds": []
    }
  ],
  "checks": [...],
  "checksDeprecated": true,
  "budgetEstimate": 0,
  "updatedAt": "2026-08-20 21:54:10"
}
```

> 响应中保留了 `category` / `intent` / `locationName` / `images` 等**向后兼容字段**（老数据可能含值），新建预定点这些字段为 `null` 或空。
> `latest` 为后端推导值（由 `dayIndex` → `planned`），前端可忽略。

### 1.3 行为规则

- **纯追加**：每次调用在 places 末尾追加一个点，不改变已有任何点
- **clientId**：由服务端生成（格式 `p_` + 时间戳 base36 + 4 位随机），前端**不传入**但会在响应返回
- `dayIndex`：从 `recordedAt` 日期减去旅程 `startDate` 自动计算（1-based）；缺 `recordedAt` 或 `startDate` 时为 null
- `sortOrder` = 当前 places 长度（追加到末尾）
- 若 `recordedAt` 有值，后端自动在 timeline 创建一条占位 entry（`source='plan_place'`），同 `plan/save` 行为
- `tags` 是前端自由格式字符串数组，后端不做枚举校验（不限制值）

## 2. 删除预定点：`POST /dream/v1/journeys/plan/place/delete`

不变（记录在本文档供对照）：

```json
{
  "journeyId": "9e8d9327-...",
  "clientId": "p_mt1l0bjy9ca6"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `journeyId` | 是 | 旅程 id |
| `clientId` | 是 | 点的 clientId（create 返回的，**不是 name**） |

- 幂等：clientId 不存在时返回现状（不报错）
- 联动删除该点创建的占位 entry（仅 `source='plan_place'`，不误删用户内容）

## 3. 编辑预定点（批量）：`POST /dream/v1/journeys/plan/save`

编辑已有预定点仍走 `plan/save`（整包提交），入参格式不变：

```json
{
  "journeyId": "9e8d9327-...",
  "places": [
    {
      "clientId": "p_mt1l0bjy9ca6",
      "name": "武侯祠（已去）",
      "tags": ["sight", "done"],
      "mediaIds": ["c4e86a00-..."],
      "lat": 30.646,
      "lng": 104.048
    }
  ]
}
```

> **与计划的区别**：`plan/save` 接收**完整的 places 数组**（包括 clientId），按 clientId 合并。前端必须先 `plan/get` 拿到当前全量 places，修改后整包提交。
> `plan/save` 新增了 `tags` 和 `mediaIds` 字段支持，旧字段（category/intent/images）仍兼容。

### 4.2 PlanPlace 类型

**`mini/src/types/index.ts`**（或 `plan.ts`）

```diff
  export interface PlanPlace {
-   clientId?: string          // 新建时不传
+   // clientId 仅编辑/删除时使用，新建由服务端生成
+   clientId?: string
    name: string
-   locationName?: string      // 合并到 name
```

### 4.3 新建时前端不再传的字段

- 删除 `clientId`（create 不传）
- 删除 `locationName`（只用 `name`）
- 删除 `category` / `intent`（合并到 `tags`）
- 删除 `images`（改用上传 → 收集 mediaId → 传 `mediaIds`）
- 删除 `cover`（统一 `coverUrl`）
- 删除 `latitude` / `longitude`（统一 `lat` / `lng`）
- 删除 `visitTime` / `dayIndex`（统一 `recordedAt`，后端自动派生）

### 4.4 新建预定点时的图片上传

与记录新建流程相同：上传媒体 → 收集返回的 `id` → 放在 `mediaIds` 提交

```ts
// 上传图片流程（复用 uploadMedia）
const media = await uploadMedia({
  ownerType: 'entry',
  ownerId: '',    // 不由预定点先占
  filePath: localPath,
  kind: 'image',
})
// 收集 id
mediaIds.push(media.id)

// 提交创建
createPlanPlace(journeyId, {
  name: '武侯祠',
  mediaIds,  // 上传返回的 id 列表
  tags: ['sight', 'must'],
})
```

## 5. 后端保证（已实测）

- **类型安全**：`PlanPlaceCreateBodyDto` 使用 class-validator 校验，name 必填且≤128 字
- **幂等**：clientId 由服务端 `Date.now().toString(36) + 4 位随机` 生成，重复概率极低
- **响应兼容**：返回 `places` 数组格式与 `plan/get` / `plan/save` 一致，前端可复用解析逻辑
- **旧数据保留**：已有预地点的 `category` / `intent` / `images` / `locationName` 字段不变
