接口契约（R1）

方法 / 路径用途关键参数返回
POST /journeys新建title, destination, dates, themeTags, companionsjourney 对象+id
GET /journeys?status=列表（按状态分组）可选 status 过滤journey[]（含花费快照）
GET /journeys/:id详情idjourney + 计划页数据
PATCH /journeys/:id编辑任意可改字段更新后 journey
POST /journeys/:id/status状态切换target新 status
DELETE /journeys/:id删除（级联）id成功，级联删 entries+guide

鉴权与校验

  • 所有接口走 JwtAuthGuard（前端 Bearer token，来自微信登录）。
  • 行级权限：user_id 必须等于当前 token 用户，防越权。
  • status 切换仅允许合法跃迁（planning↔ongoing↔ended），拒绝跳跃（如 planning 直 ended 需经 ongoing，或显式允许）。
  • themeTags/companions 做枚举白名单校验，拒绝脏值。

删除级联

DELETE /journeys/:id 事务内级联：先删 entries（含其 location/media）→ 删 guides→ 删 share_events 引用 → 最后删 journey。避免孤儿数据。前端已本地隐藏，后端失败返回错误由前端提示重试。

PART B · 增长引擎后端（永不收费）R5 一键攻略（聚合 / 归因 / 隐私）

数据模型

表字段说明
guidesid, journey_id(FK), template, payload(jsonb), cover_url, is_favorited, created_at攻略实体；payload 存聚合后的片段/路线/花费
share_eventsid, journey_id, guide_id, channel(enum), sharer_id, viewer_id(nullable), shared_at分享归因；北极星来源

聚合逻辑（输入 → 输出）

输入：该 journey 的 entries（文字/照片URL/语音转写/定位/花费）+ entry.location 打点 + expense 汇总。
处理：按时间排序取高光（照片优先）→ 提取地点名列表与路线 → 计算花费分类占比 → 拼装 payload(jsonb)。
输出：guide 对象（前端屏8 渲染）。定位坐标按 is_public 脱敏（见下）。

接口契约（R5）

方法 / 路径用途关键参数返回
POST /journeys/:id/guide生成攻略id, template(默认基础)guide 对象(payload)
GET /guides/:id拉取攻略guideId同生成结果（重看/再分享）
POST /share-events记录分享journeyId, guideId, channel成功，写入归因
POST /guides/:id/favorite收藏guideId收藏状态

指标归因（对齐北极星）

北极星 = 每周"已分享攻略"生成数 = POST /guide 成功数 ∩ POST /share-events 成功数。 share_events.channel 拆分 friend/moments/image；viewer_id 首版可空，P1 接微信 share ticket 后回填，用于群渗透率。付费转化与分享解耦——分享永远免费。

隐私脱敏

  • is_public=false 的旅程：攻略 payload 不写入精确经纬度，地点名可保留。
  • 分享前检查 journey 可见范围；私密旅程分享仅限"自己可见的卡片"，不进公开广场（公开广场属 P1）。
  • 位置数据按技术文档约定字段级加密存储。

BUILD ORDER后端构建顺序

步骤内容前端可对接
1journeys 表 + Auth(JWT) + CRUD + 状态切换列表/新建/编辑/删除
2删除级联事务 + 行级权限 + 枚举校验安全删除
3guides 表 + /guide 聚合 + /guides/:id攻略卡渲染
4share_events + /share-events + favorite分享归因 + 收藏

OPEN后端开放项

  • guide payload 结构：jsonb 字段细到什么粒度（片段/路线/花费各自子结构），需与前端屏8 对齐。
  • 状态跃迁规则：是否允许 planning 直跳 ended？建议必须经 ongoing 或显式允许。
  • viewer_id 归因：首版从简（只 channel+sharer），P1 再接微信 ticket。
  • 聚合时机：实时聚合（每次 /guide 现算）还是落地缓存（生成后存 payload）？建议落地缓存，再分享直接读。
