# 头像上传对接说明（前端）

> 日期：2026-07-25  
> Base：`/api/v1`，Header：`Authorization: Bearer <token>`  
> 现状：本地联调报错来自 **MIME 不被允许**，不是「没传 file」本身。

---

## 1. 这次报错是什么

你现在打到的是：

```http
POST /api/v1/media/local-upload
```

响应（乱码还原后）：

```text
不支持的图片类型: image/svg+xml（允许 jpeg/png/webp）
```

| 项 | 实际 |
|----|------|
| 前端传的类型 | `image/svg+xml`（SVG） |
| 后端白名单 | **仅** `image/jpeg` / `image/png` / `image/webp` |
| 文件字段名 | 必须叫 **`file`**（multipart） |

**结论**：头像不能直接丢 SVG；请先把选图限制为 jpg/png/webp，或上传前压缩/转码成其中一种。

---

## 2. 正确做法（不是「只 POST 一个 file」）

后端**没有**「`POST /media` + 一个 file 就算头像」的单接口。  
头像与其它媒体同一套三步：

```
① POST /media/prepare     JSON（声明要传头像）
② POST /media/local-upload  multipart（真正传 file）  ← 你现在卡在这一步
③ POST /media/confirm     JSON（确认后写 users.avatar）
```

本地驱动（`STORAGE_DRIVER=local`，开发默认）时，`prepare` 返回的 `uploadUrl` 就是 `/media/local-upload`。  
生产若切 COS，第 ② 步改为按返回的 `method/headers` 直传云，**第 ①③ 不变**。

---

## 3. 逐步契约

### 3.1 `POST /media/prepare`

```json
{
  "ownerType": "avatar",
  "ownerId": "<当前登录用户 id>",
  "kind": "image",
  "mime": "image/jpeg",
  "sizeBytes": 204800
}
```

| 字段 | 说明 |
|------|------|
| `ownerType` | 固定 `"avatar"` |
| `ownerId` | **必须等于当前 userId**（与 JWT 用户一致） |
| `kind` | `"image"` |
| `mime` | 与真实文件一致：`image/jpeg` \| `image/png` \| `image/webp` |
| `sizeBytes` | 文件字节数；图片 ≤ 10MB |

**响应要点**

```json
{
  "mediaId": "...",
  "uploadUrl": "http://127.0.0.1:3000/api/v1/media/local-upload",
  "method": "POST",
  "fields": {
    "mediaId": "...",
    "confirmToken": "..."
  },
  "confirmToken": "...",
  "driver": "local"
}
```

### 3.2 `POST /media/local-upload`（本地）

`multipart/form-data`：

| 字段 | 来源 |
|------|------|
| `file` | 二进制文件（字段名必须是 `file`） |
| `mediaId` | prepare 返回 / `fields.mediaId` |
| `confirmToken` | prepare 返回 / `fields.confirmToken` |

小程序示例：

```js
wx.uploadFile({
  url: prepare.uploadUrl,
  filePath: tempFilePath, // 必须是 jpg/png/webp
  name: 'file',
  header: { Authorization: `Bearer ${token}` },
  formData: {
    mediaId: prepare.mediaId,
    confirmToken: prepare.confirmToken,
  },
});
```

H5 / 浏览器：

```js
const fd = new FormData();
fd.append('file', file); // File，type 为 image/jpeg|png|webp
fd.append('mediaId', prepare.mediaId);
fd.append('confirmToken', prepare.confirmToken);
await fetch(prepare.uploadUrl, {
  method: 'POST',
  headers: { Authorization: `Bearer ${token}` },
  body: fd,
});
```

### 3.3 `POST /media/confirm`

```json
{
  "mediaId": "<同上>",
  "confirmToken": "<同上>",
  "width": 400,
  "height": 400
}
```

成功后：

- 返回媒体 DTO（含 `url`）
- **后端自动**把 `users.avatar` 写成该 `url`（`local-upload` 成功时也会先写一次，confirm 再幂等同步）
- 前端应用 confirm/`media.url` 立刻更新本地 store，并再 `GET /user/profile` 校对

展示 local URL（如 `/api/v1/files/yyyy/mm/dd/xxx.jpg`）时**必须用带鉴权的组件**（如 `AuthImage` / `resolveMediaUrl`），裸 `<image :src="url">` 会 401，看起来像「没改上头像」。

---

## 4. 前端选型与限制（必做）

| 项 | 要求 |
|----|------|
| 可选格式 | jpg / jpeg / png / webp |
| **不要选** | svg、gif、bmp、heic（未在白名单） |
| `chooseImage` / `<input accept>` | 限制为图片，并在上传前校验 `file.type` |
| SVG 头像 | **不支持**；需前端转成 png/jpeg 再传 |

推荐校验：

```ts
const OK = ['image/jpeg', 'image/jpg', 'image/png', 'image/webp'];
if (!OK.includes(file.type)) {
  throw new Error('头像仅支持 JPG / PNG / WEBP');
}
```

`prepare.mime` 与实际上传文件的 `mimetype` 都应落在白名单内（`local-upload` 会再验一次真实文件类型）。

---

## 5. 常见错误对照

| 现象 | 原因 | 处理 |
|------|------|------|
| 400：`不支持的图片类型: image/svg+xml` | 传了 SVG | 换 jpg/png/webp |
| 400：`file required` | 字段名不是 `file`，或未 multipart | `name: 'file'` / `FormData.append('file', …)` |
| 400：`confirmToken 无效` | 未带 / 带错 / 过期 | 用同一次 prepare 的 token |
| 403：`avatar ownerId must be current user` | `ownerId` ≠ 当前用户 | 用登录用户 id |
| 直接 `POST /media` | 无此上传入口 | 走 prepare → upload → confirm |

---

## 6. 勿混用的旧接口

| 接口 | 状态 |
|------|------|
| `POST /media/prepare` + upload + confirm | **正式**（头像用这个） |
| `POST /user/avatar/presign` | 旧预签名，勿新写 |
| `GET /media/upload-url` | 已废弃 |

---

## 7. 最小验收

1. 选一张 **jpg/png/webp**  
2. prepare（`ownerType=avatar`）→ local-upload（`file`）→ confirm  
3. `GET /me` 的 `avatar` / `avatarUrl` 已更新  
4. 再试 SVG → 应在前端拦截；若绕过则后端仍 400（预期）

---

## 8. 和「只传一个 file」的差距

| 你以为的 | 实际 |
|----------|------|
| 一个「上传头像」接口收 file | 三步：声明 → 传文件 → 确认落库 |
| file 任意图片 | 仅 jpeg/png/webp |
| 传完就算头像 | 必须 **confirm** 后才写 `users.avatar` |

按第 3 节改前端即可；当前 400 **不需要改后端白名单**（刻意不收 SVG）。
