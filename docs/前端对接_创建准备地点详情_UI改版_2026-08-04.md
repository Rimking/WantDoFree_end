# 前端对接 · 创建/准备/地点/详情 UI 改版接口与数据契约（2026-08-04）

> **文档类型**：后端配合清单（API / 数据模型）  
> **对齐前端**：新建旅程、准备页、添加地点、进行中详情（四页 UI PRD 已落地）  
> **Base**：`/api/v1` · JWT 用户；**勿传 userId**  
> **产品命名**：「游记」= 接口资源 `guide` + 工作台四态 `handbook`  
> **地点模型硬约束**：`plan.places`（预定打卡点）≠ `Recording.location`（自由打卡），禁止混算进同一地图/同一 `placeCount`  
> **数据原则（本轮明确）**：**展示与状态尽量以接口返回为准，禁止长期依赖本地 storage 作为真源**；本地仅作离线缓冲 / 失败重试（outbox）

> **后端落地进度（2026-08-04）**：Batch A/B/C 已对齐本文件契约。结构化地点真源 = `plan.places`（含 `intent`）；`destinations/*` 写接口返回 410。

---

## 0. 本轮为什么要动接口

四页 UI 改版后，前端字段语义已变，但部分数据仍落在「拼接字符串 / 本地缓存 / 双轨表」上，后端若不补齐会出现：

| 现象 | 根因 |
|------|------|
| 准备页「想去/已定/必去」刷新后丢失 | `plan.places.intent` 未进 `plan/save` |
| 创建时多选目的地，准备页偶发不同步 | 只写了 `Journey.destination` 字符串，结构化点靠本地 seed |
| 详情底栏「已分享」状态永远不出 | `detail` 未消费 / 未返回 `handbook` 模块 |
| 旧「目的地清单」与新「目的地」两套入口 | `destinations/*` 与 `plan.places` 双轨 |

## 2. 分页面：字段增减对照

### 2.1 新建旅程（JourneyCreate）

| UI 字段 | 必填 | 前端状态 | 建议接口字段 | 说明 |
|---------|------|----------|--------------|------|
| 封面 | 选填 | `cover` → media → `coverUrl` | `coverUrl` | 已有 `/media/prepare|confirm` |
| 旅程标题 | **必填** | `title` | `title` | — |
| 出发地 | **必填** | `origin` | `origin` | 标签单选 + 自定义 |
| 目的地（多选） | 选填 | `destinations: string[]` → join | **新增** `destinations?: string[]`；兼容 `destination` | 见 §3.1 |
| 出发/返程 | **必填** | `startDate` / `endDate` | 同左 | — |
| 主题 | 选填 | `themes` → `themeTags` | `themeTags` | — |
| 同行人 | 选填（默认自己） | `companions` | `companions` | 默认 `["solo"]` |
| 预算 | 选填 | `budgetLimit` → `budgetAmount` | `budgetAmount`（分） | 同时写 plan.budgetEstimate |

**相对旧版减少的「假必填」**：封面、目的地、主题、同行人、预算——UI 不再标 `*`，接口应允许省略/空。

**创建后联动（前端现状）**：

1. `POST /journeys/create`
2. （可选）封面 upload → `POST /journeys/update`
3. `POST /journeys/plan/save`：把多选城市种子为 `places[]`（`intent: "wish"`）
4. 再 `plan/save` 写预算

**「先不计划，直接开始」**：create 后 `POST /journeys/status` `{ target: "ongoing" }`，进详情。

### 2.2 准备页（JourneyPlan）

| UI 模块 | 数据源（期望） | 接口 | 字段变化 |
|---------|----------------|------|----------|
| 标题 / 改名 | journey | `journeys/update` | 无新增 |
| 概览：出发地、天数、预算 | journey + plan | `get` / `plan/get` / `update` | 预算未设展示「未设置」，勿强制 0 当「已设」 |
| **目的地（统一入口）** | **仅 `plan.places`** | `plan/get` · `plan/save` | **新增 `intent`**；去掉 destinations 入口 |
| 出发前准备 | checklist | `checklist/list` · `checklist/toggle` | 已对齐；勿再经 plan.checks 双写 |
| 路线预览 | `plan.places`（有 lat/lng 才上图） | 同 plan | 条件显隐，无新接口 |
| 智能 CTA | 本地根据 places/budget | — | 行为前端；数据仍靠 plan/journey |

**去掉的双入口**：

- ❌「想去的地方」单独一块 + ❌「目的地清单」跳 `destinations/*`
- ✅ 合并为「目的地」→ 只读写 `plan.places`

**`intent` 枚举（产品）**：

| 值 | 含义 | UI 标签 |
|----|------|---------|
| `wish` | 想去（未排期） | 想去 |
| `planned` | 已定 | 已定 |
| `must` | 必去 | 必去 |

兼容：无 `intent` 时，`dayIndex > 0` → 视为 `planned`，否则 `wish`。**`must` 无法从 dayIndex 推导，必须持久化。**

### 2.4 进行中详情（JourneyDetail）

| UI | 旧 | 新 | 接口诉求 |
|----|----|----|----------|
| 首屏 | 大封面 + 多块概览 | 缩略头图 + **时间线前置** | `detail` include `entries` |
| 概览 | 平铺地图/花费/手帐 | **折叠一行**（默认收起） | `plan` + `expense` + `journeyStats` |
| 中部手帐预览 | 有 | **移除平铺入口** | 能力并入底栏 CTA |
| 底栏「游记」 | 单字「游记」 | 「生成游记 / 查看游记」+ 副文案 | **读 `handbook.phase`** |
| Day 折叠 | 无 | 非今日默认折叠 | 纯前端 |

**CTA 状态机（与 handbook 四态一致）**：

| `handbook.phase` | 主文案 | 副文案方向 |
|------------------|--------|------------|
| `need_more` | 生成游记 | 还差 N 条记录就能出稿 |
| `ready` | 生成游记 | 把记录变成精美攻略 |
| `generated` | 查看游记 | 已就绪，可分享 |
| `shared` | 查看游记 | 已分享 · 浏览量等 |

前端过渡态：本地用 `recordCount` + 是否有 guide 推算，且 **`isShared` 暂无法判定**。  
**请 `POST /journeys/detail` 返回 `handbook`（同 `/journeys/handbook/list` 单条结构）**，前端改为优先读服务端 phase。

## 3. 接口契约变更明细

### 3.1 旅程 Create / Update

```http
POST /journeys/create
POST /journeys/update
```

**现有 body（前端 `toJourneyBody`）**：

```json
{
  "clientId": "j_xxx",
  "title": "下江南·杭苏5日",
  "origin": "杭州",
  "destination": "苏州 · 乌镇",
  "startDate": "2026-08-03",
  "endDate": "2026-08-07",
  "coverUrl": "https://...",
  "themeTags": ["culture"],
  "companions": ["solo"],
  "budgetAmount": 420000,
  "isPublic": false
}
```

**建议增量（P1，向后兼容）**：

```json
{
  "destination": "苏州 · 乌镇",
  "destinations": ["苏州", "乌镇"]
}
```

| 规则 | 说明 |
|------|------|
| 写 | 优先存 `destinations[]`；无则用 `destination` 按 `·`/`、`/`,` 拆 |
| 读 | 同时返回两者；`destination` = join 展示串 |
| 旧数据 | 仅有 string 时，读侧拆成数组给前端 |

**推荐 P0 增量：创建时内嵌预定点（减少二次 save）**：

```json
{
  "title": "...",
  "origin": "杭州",
  "destinations": ["苏州", "乌镇"],
  "places": [
    { "clientId": "p_xxx", "name": "苏州", "intent": "wish", "category": "SIGHT" },
    { "clientId": "p_yyy", "name": "乌镇", "intent": "wish", "category": "SIGHT" }
  ]
}
```

若暂不接内嵌 `places`，须保证随后 `plan/save` 用 `clientId` **幂等**（同 clientId 不重复插）。

### 3.2 Plan Get / Save（**本轮最关键**）

```http
POST /journeys/plan/get   { "journeyId" }
POST /journeys/plan/save  { "journeyId", "places": [...], "budgetEstimate": number }
```

**`places[]` 单项建议完整契约**：

```ts
{
  clientId: string          // 前端本地 id，幂等键
  name: string
  note?: string
  coverUrl?: string
  dayIndex?: number | null  // 1-based；null=不绑定
  category?: 'SIGHT' | 'FOOD' | 'STAY' | 'SHOPPING' | 'OTHER'
  intent?: 'wish' | 'planned' | 'must'   // ← P0 新增，必持久化
  locationName?: string
  lat?: number
  lng?: number
  // 兼容别名 latitude / longitude 亦可
  images?: string[]
  sortOrder?: number        // 建议按数组序或显式字段
}
```

**读回必须带上 `intent`**，否则准备页筛选与「必去」会丢。

**预算**：

- `budgetEstimate`：单位分；`0` / 缺省 = UI「未设置预算」
- 与 `journey.budgetAmount`：请定规则（建议 journey 为展示上限，plan 为规划估算；或创建时双向同步一次）

**废弃**：不要再要求前端经 `plan/save` 写 `checks`；准备项走 checklist 模块（见既有 2026-08-02 文档）。

---

### 3.3 Destinations 双轨收敛（P1）

| 路径 | 新 UI | 建议 |
|------|-------|------|
| `POST /journeys/destinations/list\|create\|reorder` | **不再调用** | 标记 deprecated |
| `POST /destinations/update\|delete` | **不再调用** | 同上 |
| 历史数据 | 可能仍有 | 迁移脚本：`isMust=true` → `intent=must`，其余 → `wish`/`planned`（有 dayIndex→planned），写入 `plan.places` |

验收：**全站结构化地点只认 `plan.places`**，地图只消费其中有坐标的点。

## 4. 数据真源与「少用本地缓存」要求

### 4.1 目标真源

| 领域 | 真源接口 | 前端禁止长期依赖 |
|------|----------|------------------|
| 旅程元信息 | `journeys/get` · `list` · `detail` | 仅 `storage('journeys')` 作离线 |
| 预定地点 | `plan/get` · `plan/save` | `storage('plans')` 不得在有网时覆盖远端无 intent 的脏数据 |
| 准备清单 | `checklist/list` | — |
| 时间线 | `detail.entries` / entries API | recordings 本地仅缓冲 |
| 游记四态 | `handbook` / `handbook/list` | 禁止仅用本地 recordCount 推 `shared` |
| 花费 | `expense` 聚合 | — |

### 4.2 前端将配合的改造（本清单对后端的前置依赖）

1. 准备页 / 详情：`onShow` **强制 `plan/get` + detail**，以远端覆盖本地。  
2. Detail CTA：优先 `detail.handbook.phase`；无字段才 fallback 本地推算。  
3. 创建种子：若 create 支持内嵌 `places[]`，去掉「仅本地 seed」路径。  
4. Outbox：仅断网写入；字段与正式 `toPlanBody` 对齐（含 `intent`）。

### 4.3 请后端配合的一致性

| 项 | 要求 |
|----|------|
| plan/save 幂等 | 同 `journeyId` + `clientId` 更新而非重复插入 |
| plan/get | 返回完整 places（含无坐标的 wish 点） |
| detail | 有网必含最新 `journeyStats` / `handbook` / `planProgress` |
| 错误码 | plan 校验失败勿静默丢字段（如丢 intent） |
