## 一、全局约定

| 项 | 约定 |
|---|---|
| 全局前缀 | 所有路由前加 `/dream/v1`（如 `POST /dream/v1/journeys/create`） |
| 鉴权 | 除标注「免登录」外一律 `Authorization: Bearer <token>`（JwtAuthGuard），用户身份取 JWT，**禁止从 body 传 userId** |
| 状态码 | NestJS 默认：POST=201、GET/PATCH/PUT/DELETE=200；`@HttpCode(204)` 标注的接口无响应体 |
| 校验 | 全局 ValidationPipe `whitelist: true`：未知字段被剔除，类型/枚举/长度不合法返回 400 |
| 错误 | 统一由 `HttpExceptionFilter` 处理；业务错误多为 `{ code, message }` 结构 |
| 登录 | `POST /auth/wechat-login`，dev 模式传 `code: "dev_openid_demo"` |
| 时间格式 | 入参记录时间 `YYYY-MM-DD HH:mm:ss`；出参时间统一 `YYYY-MM-DD HH:mm:ss` |
| 金额 | 一律「分」（amountCent / totalCent / priceCent） |

## 三、接口明细

### 3.1 认证

#### POST /dream/v1/auth/wechat-login（免登录）

| 项 | 内容 |
|---|---|
| 入参 | `code`：string，必填，1-64；微信登录 code（dev 模式直接传 openid） |
| 出参 | `{ token: string, user: User }`——token 为 7 天 JWT；user 为完整用户实体（含 `nick`/`nickname` 别名） |
| 逻辑 | ① wechat.code2Session(code) 换 openid → ② 按 openid 查用户，不存在则创建（status=active、plan=free）→ ③ jwt.sign({sub: userId}, expiresIn '7d') → ④ 返回 token+user |

### 3.2 旅程（journey）

#### POST /dream/v1/journeys/create

| 项 | 内容 |
|---|---|
| 入参 | `clientId?`(1-64，幂等键) · `title`* 1-128 · `origin?` 0-128 · `destination?` 0-256 · `startDate`* / `endDate`* (ISO 日期，end>=start) · `coverUrl?`/`cover?` · `themeTags?`/`themes?`（枚举或中文别名，solo 互斥校验） · `companions?` · `budgetAmount?`/`budgetLimit?`(分) · `isPublic?` · `places?[]`（内嵌预定点：clientId/name/note/coverUrl/lat/lng/locationName/category/recordedAt/visitTime/dayIndex/intent/images） |
| 出参 | `{ journey, journeyStats, planProgress, handbook }` 四模块（见 §四） |
| 逻辑 | ① endDate<startDate 抛 400 → ② clientId 幂等：同用户已存在直接返回 → ③ normalizeWrite（枚举归一、budgetAmount 转分）落库 status='planned' → ④ ensurePlan（建 plan，含默认 checks）→ ⑤ 有 places 时按 clientId 合并进 plan.places（intent 默认 wish）→ ⑥ budgetAmount 同步到 plan.budgetEstimate → ⑦ seedPlanPlaceEntries：有 name+visitTime 的点生成时间线占位记录（payload.source='plan_place'，幂等）→ ⑧ 返回四模块 |

#### POST /dream/v1/journeys/list

| 项 | 内容 |
|---|---|
| 入参 | `status?`(deprecated) · `displayStatus?`(deprecated) · `type?` ∈ 1进行中/2即将出发/3规划中/4已完成 · `keyword?`(仅匹配 title) · `startTime?`/`endTime?`(行程时间区间，与起止日有交集命中) · `page?`=1 · `pageSize?`=20(≤100) · `sortBy?` ∈ createdAt/updatedAt · `modular?`(deprecated) |
| 出参 | `{ list: 扁平卡片[], total, page, pageSize }`；卡片字段见 §四 toListCardItem |
| 逻辑 | ① 全部筛选条件下拉出全集（listFiltered：状态/展示态/类型/关键词/时间区间排序）→ ② 内存分页 → ③ 每项 toListCardItem（扁平化，不含 handbook） |

#### POST /dream/v1/journeys/handbook/list

| 项 | 内容 |
|---|---|
| 入参 | `phase?`：筛选游记阶段（如 need_more/ready） |
| 出参 | `{ minRecords, total, list: 四模块[] }`；传 phase 时加 `phase` 字段且 list 已过滤 |
| 逻辑 | ① 遍历用户全部旅程 → toModularListItem → enrichHandbook（统计记录数/游记/分享摘要，计算 phase）→ ② 按 phase 过滤 |

#### POST /dream/v1/journeys/get

| 项 | 内容 |
|---|---|
| 入参 | `id`* 1-64 |
| 出参 | `{ journey, journeyStats, planProgress, handbook }` |
| 逻辑 | journey.detail(userId,id)（owned 校验）→ 四个 toXxxModule 映射（**不含** plan/entries/expense/guide，那些走 detail） |

#### POST /dream/v1/journeys/detail（P0 详情聚合）

| 项 | 内容 |
|---|---|
| 入参 | `journeyId?`/`id?` 二选一必填 · `include?[]` ∈ entries/plan/expense/guide/handbook（缺省全部） |
| 出参 | 根上 `{ journey, journeyStats, planProgress, handbook, ...按 include 附加 }`：`plan`（toPlanModule）· `entries`（toEntryModule[]）· `expense`（toExpenseModule）· `guide`（getForAggregate 不含资格信息） |
| 逻辑 | ① 取 journey 基础聚合 → ② 按 include 集合逐项懒加载（plan 走 getPlan、entries 走 listByJourney、expense 走 summary、guide 走 getForAggregate(...,false)）→ ③ 组装返回 |

#### POST /dream/v1/journeys/update

| 项 | 内容 |
|---|---|
| 入参 | `id`* + 与 create 相同的可改字段（title/origin/destination/startDate/endDate/coverUrl/themeTags/companions/budgetAmount/isPublic 等） |
| 出参 | 四模块（同 create） |
| 逻辑 | ① owned 校验 → ② normalizeWrite → ③ end<start 抛 400 → ④ 落库 → ⑤ 若 startDate 变化，重排 plan.places 的 dayIndex → ⑥ 返回 |

#### POST /dream/v1/journeys/delete

| 项 | 内容 |
|---|---|
| 入参 | `id`* |
| 出参 | `{ deleted: true }` |
| 逻辑 | 事务内 owned 校验 → manager.remove(journey)（plan 由 FK CASCADE 删除） |

#### POST /dream/v1/journeys/status

| 项 | 内容 |
|---|---|
| 入参 | `id`* + `target?`/`status?`（planned/ongoing/finished，别名 planning/ended） |
| 出参 | 四模块 |
| 逻辑 | owned → 状态机校验（仅允许相邻迁移）→ syncVersion+1 → 落库（finished 时若 endDate 在未来收口为今天） |

#### POST /dream/v1/journeys/finish

| 项 | 内容 |
|---|---|
| 入参 | `id`* |
| 出参 | 四模块 |
| 逻辑 | ① owned → ② 已 finished 直接返回现状 → ③ 非 ongoing/planned 抛 400 → ④ status='finished'、syncVersion+1、endDate>今天则收口为今天 → ⑤ 落库返回 |

### 3.3 旅行计划（plan）

#### POST /dream/v1/journeys/plan/get

| 项 | 内容 |
|---|---|
| 入参 | `journeyId`* |
| 出参 | `{ places[], checks[], checksDeprecated: true, budgetEstimate, updatedAt }`（toPlanModule，见 §四） |
| 逻辑 | owned → ensurePlan（无则建空 plan + 默认 checks + seedDefaults checklist）→ toPlanResponse（place 补 id/clientId 双字段、cover 兼容、intent 归一、images 兜底）→ toPlanModule |

#### POST /dream/v1/journeys/plan/save（全量覆盖，兼容旧客户端）

| 项 | 内容 |
|---|---|
| 入参 | `journeyId`* + `places?[]`（同上，含 sortOrder）· `checks?[]`（clientId/text/done）· `budgetEstimate?`(分) |

#### POST /dream/v1/journeys/plan/place/upsert ⭐（单点新增/编辑，新契约）

| 项 | 内容 |
|---|---|
| 入参 | `journeyId`* + `place`*：`clientId`*(1-64) · `name`*(1-128) · `note?`/`coverUrl?`/`cover?` · `category?` · `locationName?`/`address?` · `recordedAt?`(`YYYY-MM-DD HH:mm:ss`，推荐) / `visitTime?`(deprecated) · `lat?`/`lng?`/`latitude?`/`longitude?` · `dayIndex?`(deprecated) · `intent?`(wish/planned/must) · `images?[]` |

| 逻辑 | ① owned + ensurePlan → ② normalizePlaceInput（只规范这一个点）→ ③ 按 clientId 查找：**已存在**→mergeSinglePlacePatch（只覆盖请求里显式出现的字段，保持原位置与 sortOrder，未传字段保留原值）；**不存在**→追加到末尾 → ④ 落库 → ⑤ seedPlanPlaceEntries → ⑥ 返回 |
| 契约 | docs/前端对接_预定点单点接口_2026-08-20.md |

## 五、已知约定与注意事项

1. **金额单位**：budgetAmount/budgetEstimate/amountCent/totalCent/priceCent 全为「分」；旧字段 `amount`/`budgetLimit` 兼容入参（服务端按分解释）。
2. **计划进度双写过渡**：`plan.checks` 仍在返回（checksDeprecated:true），但**读写真源是 /checklist**；plan/save 传 checks 仍会被写，仅用于旧客户端兜底。
3. **预定点→记录**：有 name+visitTime 的预定点会在 sync 时生成占位记录（payload.source='plan_place'）；删除该点会自动联动删除占位（不误删用户内容）。
4. **兼容端点已全部下线（2026-08-20）**：列表/详情/更新等一律 POST + body（静态路径优先），旧 GET/PATCH/DELETE + 路径参数访问返回 404；`/journeys/:id/...` 动态路径在 Nest 路由匹配上优先级低于静态路径，无需担心冲突。
5. **免登录接口**：/auth/wechat-login、/shares/:token、/shares/:token/view、/membership/plans、/pay/notify、/pay/dev-complete(DevOnly)。
6. **速率限制**：/stats/* 全系列有 StatsRateLimitGuard。
7. **dev 支付**：DEV_PAY_NOTIFY_SECRET 默认 'tuji_dev_pay'；`/pay/dev-complete` 需 Header `X-Dev-Pay-Secret`。
8. **整模块下线**：draft（草稿）、invite（邀请查询/接受）、quota（/me/quota）、guide 收藏、share-events 登记、map 旧接口均已移除；`membership` 开单仍会触发 `InviteService.onInviteeActivated` 邀请奖励，`draft`/`invite`/`share_event` 表数据保留不删。
