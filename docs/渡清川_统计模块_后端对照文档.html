渡清川 · 统计模块 后端对照文档

版本 v1.0 · 面向对象：后端（NestJS + Prisma + PostgreSQL）· 关联：《渡清川_统计模块_PRD.html》《渡清川_统计模块_前端对照文档.html》· 状态：待评审
本文用途：作为字段权威源，定义统计模块 6 个接口的请求校验、响应 schema、聚合逻辑、错误码、快照与缓存策略。前端文档中的 TS 类型必须与本文一一对应。

一、通用约定

  • 鉴权：Authorization: Bearer <token>；userId 由 token 解析，禁止接收前端传入的 userId（防越权，见 PRD 八）。
  • 统一响应：{ "code": 0, "message"?: string, "data": object, "range"?: {type,start,end} }；code=0 成功，非 0 为业务错误。
  • range 参数：rangeType ∈ {all, year, month, custom}；custom 必须带 start/end（ISO8601 日期，如 2026-07-01）；缺失默认 all。
  • 金额单位：一律分（整数），避免浮点；前端展示时 ÷100。
  • 限流：统计聚合接口按 userId 限流（建议 20 req/min），防刷快照/全表扫。

二、错误码表

code含义处理
0成功—
401未认证 / token 失效前端跳登录
403越权（访问非本人数据）提示无权限
400参数非法（rangeType 非法 / custom 缺 start、end / journeyId 格式错）提示参数错误
404资源不存在（journeyId 不存在或非本人）提示未找到
429请求过于频繁稍后重试
500服务内部错误重试 / 告警

三、接口定义

3.1 GET /stats/overview

Query：rangeType(req), start/end(custom 时 req), journeyId(opt)

响应 data：

字段类型说明
totalRecordsnumber累计有效记录数（北极星候选）
totalDaysnumber累计旅行天数
totalExpensenumber(分)累计花费
totalPlacesnumber累计去重地点数
streakDaysnumber | null连续记录天数（P1，未实现返回 null）
insightstring一句话洞察，后端拼装
 
// 聚合逻辑（示意）
const [rec, days, exp, places] = await Promise.all([
  prisma.recordEntry.count({ where:{ userId, ...dateFilter } }),
  prisma.journey.aggregate({...}),         // 日期差求和（仅已完成/已发生）
  prisma.expense.aggregate({ _sum:{amount}, where:{ userId, ...dateFilter } }),
  prisma.recordEntry.groupBy({ by:['locationId'], where:{ userId, ...dateFilter } })
])
const insight = `你已记录 ${rec} 条，走过 ${places.length} 个地方`

五、快照策略（UserStatsSnapshot）

连续天数、完成度分布等计算成本高，建议落地物化快照，避免每次打开全表扫。

// prisma/schema.prisma 片段
model UserStatsSnapshot {
  id            String   @id @default(cuid())
  userId        String
  date          DateTime // 按天
  totalRecords  Int      @default(0)
  totalDays     Int      @default(0)
  totalPlaces   Int      @default(0)
  streakDays    Int      @default(0)
  totalExpense  BigInt   @default(0)  // 分
  updatedAt     DateTime @updatedAt
  @@unique([userId, date])
}

更新策略：① T+1 凌晨批量物化全量；或 ② 写时增量（新增记录/完成事项时更新计数器）。一期可用定时任务，二期改增量。

六、缓存与性能

  • 聚合结果按 userId + rangeType + 参数哈希 缓存 Redis，TTL 5min。
  • 高频计数器（totalRecords/photoCount）走快照/增量，不实时全表 count。
  • 所有统计查询必须带 userId 索引过滤，禁止跨用户。

七、权限与隐私

  • userId 一律从 token 取，入参 journeyId 须校验归属本人，否则 403/404。
  • 消费金额、地点属敏感数据，列表接口不对外分享；分享仅限手帐成品。
  • 存储统计不返回具体文件列表。

八、验收标准

  • P0 维度数据与实际一致，误差 < 1%。
  • range 切换后所有维度联动刷新，无报错。
  • 统计页接口 P95 < 800ms（有快照/缓存前提下）。
  • 越权访问返回 403。
