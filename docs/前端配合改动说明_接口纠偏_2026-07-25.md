# 前端配合改动说明（接口纠偏 2026-07-25）

> 对齐后端本轮纠偏。权威契约仍见 [`前端对接接口文档_2026-07-24.md`](./前端对接接口文档_2026-07-24.md)。  
> **只列前端需要改或必须知晓的破坏性/行为变化**；纯后端内部修复不重复展开。

---

## 1. 必须改（破坏性）

### 1.1 金额：`amount` 一律按「分」

| 场景 | 旧行为 | 新行为 |
|------|--------|--------|
| `POST …/entries/sync` 的 `expense.amount` | 按分 | **按分**（不变） |
| `POST /records/update` · `PATCH /records/:id` 的 `expense.amount` | 可能按「≥1000 当元」启发式 | **一律按分**；优先 `amountCent` |

**前端动作**：编辑记录写金额时，若原先传元（如 `180`），改为传分（`18000`），或改用 `amountCent`。

### 1.2 旅程写接口响应改为模块化（新 POST）

下列 **新契约 POST** 成功响应与 `POST /journeys/get` / `list` 同构：

```json
{
  "journey": { "...": "..." },
  "journeyStats": { "...": "..." },
  "planProgress": { "checkDone": 0, "checkTotal": 4, "pct": 0 }
}
```

| 方法 | 路径 |
|------|------|
| POST | `/journeys/create` |
| POST | `/journeys/update` |
| POST | `/journeys/status` |
| POST | `/journeys/finish` |

**前端动作**：不要再从根上读 `title` / `status`；改读 `res.journey.*`。  
旧 path（`POST /journeys`、`PATCH /journeys/:id`、`POST /journeys/:id/finish`）仍返回**平铺**，仅兼容一期。

### 1.3 `planProgress.checkTotal` 语义修正

| 字段 | 含义 |
|------|------|
| `checkDone` | 已勾选数 |
| `checkTotal` | **检查项总数**（含未勾选）；全未勾选时为总数，**不再是 0** |
| `pct` | `round(done/total*100)`；total=0 时为 0 |

**前端动作**：进度文案用 `checkDone/checkTotal`，勿再把 `checkTotal===0` 当成「无计划」。

### 1.4 花费 / 手帐：新旧接口响应同构

| 能力 | 推荐 | 响应 |
|------|------|------|
| 旅程花费 | `POST /journeys/expense/summary` | expense 模块（`totalCent` / `byCategory[].amountCent`） |
| 同上（兼容） | `GET /journeys/:id/expense-summary` | **已改为与 POST 同构模块**（不再平铺双轨） |
| 手帐读取 | `POST /journeys/guide/get` | 无攻略时返回 `{ exists:false, canGenerate }`，不抛 404 |
| 同上（兼容） | `GET /journeys/:id/guide` | **已与 POST 同构** |

**前端动作**：统一按模块字段解析；若曾依赖 GET expense 根上的平铺 `amount`，改为 `amountCent` / 模块结构。

### 1.5 统计花费：`amountCent` 为主

`POST/GET /stats/expenses`（及 dashboard 内 expenses）：

- 正式字段：`totalCent`、`byCategory[].amountCent`、`trend[].amountCent`、`byJourney[].amountCent`
- 兼容期仍双写同值 `total` / `amount`

**前端动作**：新代码只读 `*Cent`；勿再假设只有 `amount`。

### 1.6 本地文件回读鉴权收紧

`GET /files/:y/:m/:d/:file`：**开发与生产均需** JWT，且校验媒体所有权。  
非本人 storageKey → `403 file not owned`。

**前端动作**：本地联调预览图也必须带登录态；勿用裸 URL 测他人文件。

## 2. 建议改（契约补齐，旧 path 仍可用）

### 2.1 新增 POST 别名（有参走 body）

| 域 | 新 POST | Body 要点 | 旧兼容 |
|----|---------|-----------|--------|
| 目的地 | `/journeys/destinations/list\|create\|reorder` | `journeyId` + 业务字段 | GET/POST/PATCH path |
| 目的地 | `/destinations/update\|delete` | `{ id, … }` | PATCH/DELETE `/:id` |
| 清单 | `/journeys/checklist/list\|create\|reorder` | `journeyId` + 业务字段 | path 版 |
| 清单 | `/checklist/update\|toggle\|delete` | `{ id, … }` | PATCH/DELETE |
| 草稿 | `/drafts/list\|get\|save\|delete` | `kind?` / `id` / upsert | GET/PUT/DELETE |
| 位置清理 | `/me/locations/clear`、`/journeys/locations/clear` | 后者 `{ journeyId }` | DELETE |
| 记录时间 | `/records/time` | `{ recordId, recordedAt, dayIndex? }` | `PATCH /records/:id/time` |
| 分享归因 | `/share-events/viewer` | `{ id, viewerId }` | `PATCH …/viewer` |

### 2.2 媒体 kind 写入对齐

sync / media 写入接受：`image` \| `audio`（规范）以及兼容 `photo` \| `voice`。  
**读出**仍以规范 `image` \| `audio` 为准（见媒体同步方案）。

### 2.3 entries sync 校验变严

`POST /journeys/entries/sync` 的 `entries[]` 现做嵌套 DTO 校验。  
非法 `category` / 缺 `clientId` / 非法 kind → **400**，不再静默进业务。

---

## 3. 可不改（知晓即可）

- 旧 GET 旅程列表 / 详情仍平铺；新对接继续用 `list` / `get` / `detail`。
- `amount` 在多数读接口仍与 `amountCent` **同值双写**（兼容期）。
- `/map/*` 与 `/pois/*` 重复能力：新对接以 `/pois/*` POST 为准。
