# 渡清川 · 前后端接口同步说明（基于当前前端实现）

> **依据**：仓库当前前端代码（`src/api/*`、`src/types/*`、`src/stores/*`、`src/lib/statsLocal.ts`、统计相关页面）  
> **目的**：前端已落地能力与后端契约不同步，本文列出**需新增 / 需更新 / 需调整**的接口与参数，供后端对齐。  
> **日期**：2026-07-24  
> **约定 Base**：`/api/v1`（见 `src/config/env.ts`）  
> **鉴权**：`Authorization: Bearer <token>`；业务成功码默认 `code === 0`（若后端返回裸 JSON，请求层亦兼容）

---

## 0. 结论摘要

| 类别 | 说明 |
|------|------|
| **必须新增（P0）** | 统计模块 6 个只读接口：`/stats/*`（前端已接线，失败则本地聚合兜底） |
| **建议更新（P0/P1）** | 旅程状态写入与列表展示、结束旅程后手帐生成、配额结构与存储统计对齐 |
| **建议调整（P1）** | 全局花费汇总与统计消费维度字段统一、POI 路径命名、计划地点坐标字段 |
| **可暂缓** | 统计 P1 字段（`streakDays`、`completionDist`、`handbookCount` 等）允许返回 `null` |

**前端现状**：统计 Tab 已替换原「记账」Tab；`statsApi` 优先请求后端，**失败静默走本地聚合**，联调前不阻塞 UI，但数据口径可能与后端不一致。

## 1. 通用约定（前后端必须一致）

### 1.1 时间筛选 Query（统计模块共用）

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `rangeType` | `'all' \| 'year' \| 'month' \| 'custom'` | 是 | 全部 / 本年 / 本月 / 自定义 |
| `start` | `string` (ISO date，`YYYY-MM-DD`) | `custom` 时必填 | 含当日 00:00 |
| `end` | `string` (ISO date) | `custom` 时必填 | 含当日 23:59:59；须 ≥ start；跨度建议 ≤ 2 年 |
| `journeyId` | `string` | 否 | 按单旅程下钻 |
| `status` | `string` | 否 | 旅程维度筛选，见下表 |

**`status` 取值（统计旅程维，前端传入）：**

| 值 | 含义 | 对应前端展示态 |
|----|------|----------------|
| `ongoing` | 进行中 | `ongoing` |
| `planning` | 规划中 + 即将出发 | `planning` / `departing` |
| `completed` | 已完成 | `finished` |
| `draft` | 草稿（若后端无草稿实体可返回 0） | 草稿箱计数 |

### 1.2 金额与比例

| 约定 | 说明 |
|------|------|
| 金额 | **整数，单位：分**（前端 `formatMoney` 除 100 展示） |
| `ratio` | **0~1 小数**（非百分比整数） |
| 时间字段 | ISO8601 字符串 |

### 1.3 响应形态（推荐）

```json
{
  "code": 0,
  "data": { },
  "message": "ok",
  "range": {
    "type": "month",
    "start": "2026-07-01",
    "end": "2026-07-31"
  }
}
```

`range` 可选；前端当前主要消费 `data`（或裸对象）。`code !== 0` → 错误；`401` → 跳转登录。

## 2. 【必须新增】统计模块接口（P0）

前端封装：`src/api/stats.ts`  
类型定义：`src/types/stats.ts`  
本地兜底：`src/lib/statsLocal.ts`

### 2.1 `GET /stats/overview`

**用途**：统计总览 KPI + 洞察文案。

**Query**：`rangeType`、`start?`、`end?`、`journeyId?`（一般总览不带 status）

**Response `data`（`OverviewData`）**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `totalRecords` | `number` | 记录条数 |
| `totalDays` | `number` | 旅程天数合计（按旅程起止日跨度求和） |
| `totalExpense` | `number` | 总花费（**分**） |
| `totalPlaces` | `number` | 去重打卡点 |
| `streakDays` | `number \| null` | 连续记录天数；**P1，未做返回 null** |
| `insight` | `string` | 洞察文案（纯展示，如「计划去 X 个地方，已记录 Y 个…」） |

---

### 2.2 `GET /stats/expenses`

**用途**：消费统计（环形分类 + 趋势 + 按旅程）。

**Query**：共用 range + `journeyId?`

**Response `data`（`ExpensesData`）**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `total` | `number` | 总花费（分） |
| `currency` | `string` | 如 `"CNY"` |
| `byCategory` | `CategoryItem[]` | 分类占比 |
| `trend` | `TrendPoint[]` | 趋势点 |
| `byJourney` | `JourneyExpenseItem[]` | 按旅程花费 |

**`CategoryItem`**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `category` | `string` | 见分类枚举 |
| `amount` | `number` | 分 |
| `ratio` | `number` | 0~1 |

**花费分类枚举（与前端 `ExpenseCategory` 对齐）**：

```text
food | stay | transport | ticket | shopping | other
```

对应中文：餐饮 / 住宿 / 交通 / 门票 / 购物 / 其他。

**`TrendPoint`**：`{ date: string, amount: number }`  
- `date`：ISO 日期或 `YYYY-MM`；前端折线图按序展示  
- `amount`：分  

**`JourneyExpenseItem`**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `journeyId` | `string` | |
| `name` | `string` | 旅程标题 |
| `amount` | `number` | 分 |
| `ratio` | `number` | 占总花费 0~1 |

---

### 2.3 `GET /stats/plans`

**用途**：计划统计（准备完成率、目的地覆盖、预算执行）。

**Query**：共用 range + `journeyId?`

**Response `data`（`PlansData`）**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `preTripDoneRate` | `number` | 准备事项完成率 0~1 |
| `destinationCoverage` | `number` | 目的地覆盖率 0~1（已记录地点 / 想去地点） |
| `planPlaces` | `number` | 想去地点总数 |
| `visitedPlaces` | `number` | 已记录/已打卡地点数 |
| `planVsActualGap` | `number \| null` | 计划 vs 实际缺口；**P1，可 null** |
| `budgetExecutionRate` | `number \| null` | 已花/预算；无预算时 **null**；可 >1（超支） |

---

### 2.4 `GET /stats/journeys`

**用途**：旅程统计（分状态计数 + 总天数/地点）。

**Query**：共用 range + `status?`

**Response `data`（`JourneysData`）**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `totalByStatus` | `object` | 见下 |
| `totalDays` | `number` | |
| `totalPlaces` | `number` | |
| `completionDist` | `number[] \| null` | 完成度四桶；**P1，可 null** |

**`totalByStatus`**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `ongoing` | `number` | 进行中 |
| `planning` | `number` | 规划中（含即将出发聚合，或与前端一致单独算） |
| `completed` | `number` | 已完成（对应持久化 `finished`） |
| `draft` | `number` | 草稿数；无草稿体系返回 `0` |

---

### 2.5 `GET /stats/content`

**用途**：内容统计（记录/图片/语音/字数）。

**Query**：共用 range（通常不带 `journeyId`，也可支持）

**Response `data`（`ContentData`）**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `recordCount` | `number` | 记录条数 |
| `avgPerDay` | `number` | 日均记录数 |
| `photoCount` | `number` | 图片张数 |
| `voiceSeconds` | `number` | 语音总秒数 |
| `wordCount` | `number` | 文字总字数 |
| `handbookCount` | `number \| null` | 手帐生成数；**P1，可 null** |

---

### 2.6 `GET /stats/storage`

**用途**：存储配额（**不带 range**，实时配额）。

**Query**：无

**Response `data`（`StorageData`）**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `photo.used` | `number` | 已用张数 |
| `photo.limit` | `number` | 上限张数 |
| `photo.ratio` | `number` | used/limit，0~1 |
| `voice.usedSeconds` | `number` | 已用秒 |
| `voice.limitSeconds` | `number` | 上限秒 |
| `voice.ratio` | `number` | 0~1 |

**警示阈值**：前端 `ratio ≥ 0.85` 进入警示态（与首页额度卡、统计存储区一致）。

**与现有 `/me/quota` 关系**：建议 `/stats/storage` 与 `/me/quota` 同源；字段形态可不同，但 used/limit 口径必须一致。当前前端 `/me/quota` 为：

```ts
{
  plan: string
  photo: { used, quota, remaining }
  voiceSec: { used, quota, remaining }  // 秒
}
```

而本地 UserProfile 把语音存成**分钟**（`usedVoiceSec/60`）。统计页按**秒**展示转换。后端新增 storage 时请**明确单位并在文档写死**。

## 3. 【需更新】已有接口

### 3.1 旅程状态 `POST /journeys/:id/status`（P0）

**前端行为**：

- 「开始旅程」→ `target: ongoing`
- 「结束旅程」→ `target: finished`（确认弹窗后调用 `finishJourney`）

**当前前端写入映射（`toApiStatus`）**：

| 前端状态 | 写入后端 |
|----------|----------|
| `ongoing` | `ongoing` |
| `finished` | `finished` |
| `planning` / `departing` | `planned` |

**读取兼容**：`planned`→`planning`，`ended`→`finished`，亦接受 `departing`。

**需后端更新**：

1. 明确持久化枚举：至少支持 `planned | ongoing | finished`（或四态含 `departing`）。
2. `finished` 与旧值 `ended` 双向兼容。
3. 结束旅程后，列表/详情 `status` 立即为已完成；统计 `completed` 计数随之变化。

---

### 3.2 手帐生成 `POST /journeys/:id/guide`（P0）

**前端行为**：结束旅程时可勾选「同时生成最终手帐封面」→ `guideApi.create(journeyId)`，再跳转 `GuideShare`。

**需后端保证**：

| 点 | 说明 |
|----|------|
| 幂等 | 已存在 guide 时返回已有或明确错误码，前端可降级本地预览 |
| `GET /journeys/:id/guide` | 按旅程取手帐（已有）；`exists: false` / 404 表示未生成 |
| `GET .../guide/check` | `canGenerate` 规则与结束旅程场景一致 |

---

### 3.3 旅程列表/详情字段（P1，与卡片/统计相关）

前端已依赖或建议返回：

| 字段 | 用途 |
|------|------|
| `origin` / `destination` | 路线文案、手帐封面 |
| `coverUrl` / `cover` | 封面 |
| `budgetAmount` / `budgetLimit` | 预算执行率 |
| `placeCount` / `entryCount` / `totalExpenseCent` | 列表统计 |

前端目前可本地推导 `departing`（出发 ≤ 3 天），但列表规则宜以后端为准，避免漂移。

## 4. 【需调整】已有接口口径或路径

### 4.1 全局花费 `GET /me/expense-summary?year=` vs 统计消费

| | 旧记账总览 | 新统计消费 |
|--|------------|------------|
| 路径 | `/me/expense-summary?year=` | `/stats/expenses?rangeType=...` |
| 金额字段 | `totalCent` / `amountCent` | `total` / `amount`（分，无 Cent 后缀） |
| 时间维 | 仅自然年 | all / year / month / custom |

**调整建议**：

1. **保留** `/me/expense-summary` 供旧页/预算页，或标注废弃。
2. **新建** `/stats/expenses` 为统计权威源；分类码统一为 `food|stay|transport|ticket|shopping|other`（勿混用中文或其它码）。
3. 若两接口并存，**同一旅程同一时期总额必须相等**。

---

### 4.2 单旅程花费 `GET /journeys/:id/expense-summary`

前端映射同时兼容 `totalCent` 与 `total`。  
**建议调整**：响应统一一种命名（推荐 `totalCent` + `byCategory[].amountCent`），并在文档写死；统计下钻到 `ExpenseDetail` 仍依赖本接口。

---

### 4.3 POI 地图选点路径

前端当前调用：

| 前端 | 路径 |
|------|------|
| 附近 | `GET /pois/nearby` |
| 逆地理 | `GET /pois/reverse-geocode` |
| 搜索 | `GET /pois/search` |

若后端文档为 `/map/poi`、`/map/reverse-geocode`，**需统一路径**（改后端路由别名或改前端；当前前端以 `/pois/*` 为准，失败走 mock）。

**Query 要点**：

- nearby: `lat,lng,radius?,keyword?,page?,pageSize?`
- reverse: `lat,lng,getPoi?`
- search: `keyword,city?,lat?,lng?,page?,pageSize?`

**返回**：`{ list: PoiItem[], total }`；POI 含 `latitude/longitude`（前端不用 `lat/lng` 别名除非 mapper 补齐）。

---

### 4.4 计划 `GET|PUT /journeys/:id/plan`

前端已用 `places[].lat/lng/locationName/category/dayIndex/images`、`checks[]`、`budgetEstimate`。

**需调整确认**：

- 地点无坐标时地图不打点；统计「覆盖率」依赖「有定位的记录」与「想去地点」对比。
- `toggleCheckClientId` PATCH 语义保持稳定。

---

### 4.5 配额 `/me/quota` 与统计存储

| 问题 | 说明 |
|------|------|
| 单位 | 语音：接口为秒，前端 profile 存分钟，统计 storage 要秒 |
| 字段名 | `quota` vs `limit`；建议 `/stats/storage` 用 `limit`，`/me/quota` 可保留 `quota` 但文档注明同义 |
| 首页额度卡 | 读 `user.profile.quota`（来自 `/me` 或 `/me/quota` 合并） |

**建议**：后端提供一份「配额权威结构」，两接口都映射自同一服务。

---

### 4.6 草稿 `GET /drafts`

产品侧已弱化「我的草稿」入口，但统计旅程维仍有 `draft` 计数。  
**调整**：若产品确认无草稿，后端 `totalByStatus.draft` 恒为 `0`，可废弃 drafts 列表；若保留，计数与 `/drafts` 一致。
