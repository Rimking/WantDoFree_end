## 0. 审计结论（先读）

**主干可用，可按本文新契约联调。** 本轮全量盘点约 **120+** 路由，主链路（登录 / 旅程聚合 / 记录 sync / 媒体 / 统计 / 资料）已打通。

### 0.1 前端必须避开的坑

| 优先级 | 问题 | 前端怎么做 |
|--------|------|------------|
| **P0** | **进度条 `planProgress` 读 checklist 表**，不是 `plan.checks` | 勾选进度用 **`POST /checklist/toggle`**；勿用 `plan/toggleCheck` 驱动卡片进度 |
| **P0** | 新旧接口**响应形态不同** | 只用本文 **新 POST**；勿混用旧 GET 平铺 parser |
| **P0** | `POST entries/list` 默认 **modular**；`GET entries` / `records/update` 仍是**平铺** | 时间线只用 `entries/list`；编辑接口单独适配 |
| **P0** | 金额一律 **分** | 传 `18000` 不是 `180`；读 `amountCent` / `totalCent` |
| **P0** | 本地图 `/api/v1/files/...` 需鉴权 | 用 `AuthImage` / `resolveMediaUrl`，禁止裸 `<image>` |
| **P1** | `/user/avatar/presign`、`GET /media/upload-url` 不可用/已废弃 | 只用 `prepare → upload → confirm` |
| **P1** | `/orders` 与 `/membership/orders` 两套支付 | 会员走 membership；旧商品订单勿混 |
| **P1** | 统计有 `{ code, data }` 包装；业务接口多是**裸 JSON** | 分域解析 |
| **P2** | `/map/*` 与 `/pois/*` 重复 | 新对接只打 `/pois/*` POST |

### 0.2 后端已知逻辑债（知晓即可，勿依赖错误行为）

1. `plan.checks` 与 `checklist_items` 双写默认项，进度只认 checklist。  
2. sync 更新已有 `clientId` 时配额预检可能跳过（重复加媒体有绕过风险，后端待修）。  
3. 字典 `identities` / `regions` 仍要求登录。

## 1. 全局约定

### 1.1 方法

| 场景 | 方法 |
|------|------|
| 无业务参数获取 | **GET**（`/me`、`/me/quota`、字典） |
| 有参读取 / 全部写入 | **POST + JSON body** |
| 本地文件回读 | **GET** `/files/:y/:m/:d/:file` + Bearer |

旧 GET query / PATCH / PUT / DELETE **一期兼容**；新代码勿用。

### 1.2 响应

| 类型 | 形态 |
|------|------|
| 多数业务 | **裸 JSON** |
| `/stats/*` | `{ "code": 0, "message": "ok", "data": ... }`；`dashboard` 的 range 在 `data` 内 |
| 错误 | `{ code, message, timestamp, path }` + HTTP 非 2xx |
| 部分删除/排序 | **204 无 body** |

### 1.3 字段规范

| 项 | 规范 |
|----|------|
| 金额 | **分**；`amountCent` / `totalCent` / `budgetAmount`；`amount` 仅同值兼容 |
| 媒体 kind | 写：`image`\|`audio`（兼容 photo\|voice）；读：`media[].kind` = image\|audio |
| 用户名 | `nickname`（兼容 `nick`） |
| 封面/头像 | `coverUrl` / `avatarUrl`（兼容 `cover` / `avatar`） |
| 旅程状态写 | `planned`\|`ongoing`\|`finished` |
| 展示状态读 | `displayStatus`: `planning`\|`departing`\|`ongoing`\|`finished` |

### 1.4 缓存

业务以服务端为准；token / onboarding / outbox 可本地。勿把 journeys/stats 本地当真源。

### 3.3 旅程（模块化）

### 3.7 记录 Entries / Records

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/journeys/entries/list` | 默认 modular Entry；`{ journeyId, dayIndex?, modular? }` |
| POST | `/journeys/entries/sync` | `{ journeyId, entries[] }`；嵌套校验，非法 400 |
| POST | `/journeys/entries/delete` | `{ journeyId, entryIds? \| from/to }` |
| POST | `/records/update` | `{ recordId, ... }`；金额分；**响应平铺** |
| POST | `/records/time` | `{ recordId, recordedAt, dayIndex? }` |
| POST | `/records/delete` | `{ recordId }` |

**Modular Entry 读字段**：`location` / `expense` / `media[]` / `audio`；旧字段在 `legacy`。  
**sync 花费**：优先 `expense.amountCent`（分）；`amount` 也按分。  
**分类**：`food`\|`stay`\|`transport`\|`ticket`\|`shopping`\|`other`。

### 3.11 媒体 / 文件

## 5. 明确废弃 / 勿新写

| 路径 | 原因 |
|------|------|
| `GET /media/upload-url` | 废弃 |
| `POST /user/avatar/presign` | local 下不可用；改媒体三步 |
| `GET /map/poi`、`GET /map/reverse-geocode` | 改 `/pois/*` POST |
| `GET /journeys`、`GET /journeys/:id` | 平铺；改 list/get/detail |
| `GET /journeys/:id/entries` | 与 modular list 不同构 |
| `PUT/PATCH /journeys/:id/plan` | 响应与 POST plan 不完全同构 |
| 混用 expense/guide 的旧 GET 与新 POST parser | 已同构，但建议统一 POST |
