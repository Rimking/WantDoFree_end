## 一、统一响应结构

### 1.1 成功

所有成功响应 = `{ code: 2000, data: <业务数据>, message: '' }`（stats 的 `message` 为 `'ok'`）：

```json
// POST /dream/v1/journeys/create   → HTTP 201
{
  "code": 2000,
  "data": { "journey": { "id": "...", "title": "..." } },
  "message": ""
}
```

- **成功判定：只认 `body.code === 2000`**，不要用 HTTP 状态码判定（POST 成功是 **201**，不是 200）。
- **取数：业务数据一律从 `data` 取**（对象、数组都在 `data` 内）；写入类接口（删除/排序）`data` 为 `null`。
- `message` 成功时为空串，前端无需展示。

### 1.2 失败

```json
// HTTP 400
{
  "code": "40001",
  "data": null,
  "message": "参数错误",
  "timestamp": "2026-09-11T15:30:00.000Z",
  "path": "/dream/v1/journeys/create"
}
```

- **失败判定：`code !== 2000`**（可能是字符串业务码，注意用宽松比较/`String()` 归一）。
- `data` 恒为 `null`。
- `message` 已中文化，可直接用于 toast（参数类错误统一为「参数错误」）。
- 非生产环境会多带 `stack` 字段，前端忽略即可。
- 部分业务失败会**额外携带顶层字段**（不在 `data` 内，直接读 `body.xxx`）：

| code | 额外顶层字段 | 说明 |
|---|---|---|
| `GUIDE_NOT_READY` | `canGenerate`、`reason`、`stats` | 生成游记门槛不足，`reason` 可直接展示 |
| `40030` | `provider`、`amapInfo`、`amapInfocode` | 高德服务异常（Key/配额问题） |
| `QUOTA_EXCEEDED` | 无 | `message` 已带升级会员引导语 |
| `40901` | 无 | `message` = 「该名称已存在」 |

### 1.3 两条例外（不受包裹约束）

| 接口 | 原因 | 前端处理 |
|---|---|---|
| `GET /dream/v1/files/:y/:m/:d/:file` | 二进制文件回读 | 直接作为图片 `src` / 下载 URL 使用，**不要**按 JSON 解析 |
| `POST /dream/v1/pay/notify` | 微信支付平台回调契约（响应结构由微信定义） | 小程序前端无需调用 |

## 二、HTTP 状态码对照表

| HTTP | 何时出现 | 对应 code |
|---|---|---|
| **200** | GET/PATCH 等默认成功；3 个显式 200 的 POST：`/journeys/checklist/reorder`、`/checklist/delete`、`/me/delete` | `2000`（成功） |
| **201** | 其余全部 POST 成功（NestJS 默认） | `2000` |
| **400** | 入参校验失败、业务参数错误（日期倒挂/媒体超限/语音超 5 分钟）、配额不足、内容违禁、高德异常、游记门槛不足 | `'40001'` 或业务码（见 §3.2） |
| **401** | 未登录 / token 缺失、失效、过期 | `401` |
| **403** | 无权限（非本人资源）；生产环境微信未配置；dev 调试接口未开启 | `403`、`WX_NOT_CONFIGURED`、`DEV_DISABLED` |
| **404** | 资源不存在：旅程/分享票据/路由 | `404` 或 `'40401'`（记录/清单项已不存在）、`GUIDE_NOT_FOUND` |
| **409** | 唯一性冲突（清单名称重复） | `'40901'` |
| **410** | 分享链接已过期 | `410` |
| **429** | stats 接口限流（每用户 **20 次/分钟**） | `429` |
| **500** | 未捕获的服务器异常 | `'INTERNAL_ERROR'` |
| **503** | 微信支付 v3 未配置（真实下单不可用，mock 支付不受影响） | `503` |

> 已无 **204**（无响应体会破坏统一结构：清单 reorder/delete 由 204 改为 200 + `data:null`）。
> 未使用 413/422：媒体超限走 **400 + `'40001'`**（图片上限 10MB、音频上限 30MB、单条记录媒体最多 20 个）。

## 三、`code` 取值全表（前端对照用）

**规则**：成功恒为数字 `2000`；失败只有两种形态 —— ① **业务码**：`'4xxxx'` 数字串或大写枚举串；② **数字 HTTP 状态**（通用回落）。判失败用 `code !== 2000`，细分再按下表匹配。

### 3.1 成功

| code | 含义 | 出现范围 |
|---|---|---|
| `2000` | 成功 | 全部接口（含 stats） |

### 3.2 业务码（字符串）

| code | 含义（message 文案） | 出现接口 |
|---|---|---|
| `'40001'` | 参数错误（入参校验、日期倒挂、媒体超限、语音超 5 分钟、stats 范围参数非法等；message 统一为「参数错误」） | 全部接口（校验）/ records、media、stats |
| `'40002'` | 昵称已被占用 | `POST /user/profile/update`（报错）；`POST /user/nickname/check`（**成功的 `data` 内**，外层 `code=2000`） |
| `'40003'` | 媒体最多 20 个 / 签名过长 | records 创建与更新、`user/profile/update` |
| `'40004'` | 请至少上传一张图片、一段语音或一段文字 / 旅行身份非法 | records 创建与更新、`user/profile/update` |
| `'40005'` | 旅行身份最多选 N 个 | `user/profile/update` |
| `'40006'` | 所在地编码无效 / 省市编码不匹配 | `user/profile/update` |
| `'40030'` | 高德服务异常（Key 无效/平台不匹配/日配额用尽），带 `provider`/`amapInfo`/`amapInfocode` | `pois/nearby`、`pois/search`、`pois/reverseGeocode` |
| `'40401'` | 内容已不存在（记录/清单项已被删） | records 系列、checklist 系列、`journeys/entries/delete` |
| `'40901'` | 该名称已存在（清单项重名） | `journeys/checklist/create` |
| `'CONTENT_BLOCKED'` | 文字未通过内容安全检查 | 记录创建/更新（`journeys/entries/create`、`records/update`） |
| `'GUIDE_NOT_READY'` | 生成游记门槛不足（`reason` 可直接展示，带 `canGenerate`/`stats`） | `journeys/guide/create` |
| `'GUIDE_NOT_FOUND'` | 该旅程还没有游记（保留码；当前走聚合返回 `exists:false`，不报错） | 内部旧方法，前端按 2000 + `exists` 判断 |
| `'QUOTA_EXCEEDED'` | 照片/语音配额已用尽，升级会员可扩容 | 媒体上传、记录创建 |
| `'WX_NOT_CONFIGURED'` | 微信登录/能力未配置（生产缺配置或未开 mock） | `auth/wechat-login` 等 |
| `'DEV_DISABLED'` | 调试接口不可用（需非生产且 `ENABLE_DEV_PAY=true`） | `pay/dev-complete` |
| `'INTERNAL_ERROR'` | 未捕获的服务器异常（HTTP 500） | 全部接口 |

### 3.3 数字码（= HTTP 状态）

| code | 含义 |
|---|---|
| `401` | 未登录 / 凭证无效（统一跳登录） |
| `403` | 无权限 / 请求被拒绝 |
| `404` | 资源不存在（旅程、分享票据、路由） |
| `410` | 分享链接已过期 |
| `429` | 触发限流（stats 20 次/分钟），提示稍后重试 |
| `500` | 服务器内部错误 |
| `503` | 服务暂不可用（微信支付未接入） |

### 4.2 B 类明细（必须适配）

**1）POST /auth/wechat-login —— 数据移入 `data`**

```jsonc
// 旧：HTTP 201
{ "token": "eyJ...", "user": { /* ... */ } }

// 新：HTTP 201
{ "code": 2000, "data": { "token": "eyJ...", "user": { /* ... */ } }, "message": "" }
```

**2）stats 全部 8 个接口 —— 成功码 `0` → `2000`，且 `range` 位置不一**

```jsonc
// 旧：POST /stats/overview（其它 stats 同）
{ "code": 0, "message": "ok", "data": { /* ... */ } }

// 新：POST /stats/overview —— range 与 data 平级（顶层）
{ "code": 2000, "message": "ok", "data": { /* ... */ }, "range": { "type": "all", "start": null, "end": null } }

// 新：POST /stats/dashboard —— range 在 data 内（无顶层 range）
{ "code": 2000, "message": "ok", "data": { "range": { /* ... */ }, "overview": {}, "expenses": {}, "plans": {}, "journeys": {}, "content": {}, "storage": {} } }
```

- 限流：同一用户超过 **20 次/分钟** → HTTP 429 + `code=429`，`message="请求过于频繁，请稍后重试"`。
- 参数错误：原 stats 内部的数字 `400` 已并入全局 `'40001'`（message = 「参数错误」）。

**3）清单两个 POST 由 204 改为 200（响应体从「无」变为信封）**

| 接口 | 旧 | 新 |
|---|---|---|
| `POST /journeys/checklist/reorder` | HTTP 204，无响应体 | HTTP **200**，`{ "code": 2000, "data": null, "message": "" }` |
| `POST /checklist/delete` | HTTP 204，无响应体 | HTTP **200**，`{ "code": 2000, "data": null, "message": "" }` |

**4）错误响应（影响全部接口）**

```jsonc
// 旧（示例：旅程不存在）
{ "code": "Not Found", "message": "journey not found", "timestamp": "...", "path": "..." }

// 新
{ "code": 404, "data": null, "message": "journey not found", "timestamp": "...", "path": "..." }
```

- 新增 `data: null` 字段；
- `code` 只可能是「数字状态」或「业务码」，**不再出现 `'Not Found'`/`'Forbidden'` 这类英文描述串**；
- 参数类错误统一 `'40001'` + `message = "参数错误"`。

**5）成功但业务结果在 `data` 内的特例（外层仍是 2000）**

```jsonc
// POST /user/nickname/check → HTTP 201
{
  "code": 2000,
  "data": { "available": false, "code": "40002", "message": "昵称已被占用" },
  "message": ""
}
```

前端判断昵称占用需读 `body.data.code === '40002'` / `body.data.available`。

### 4.3 C 类（未变更，保持原样）

- `GET /dream/v1/files/:y/:m/:d/:file`：二进制流，无信封。
- `POST /dream/v1/pay/notify`：微信回调契约，无信封。

## 五、前端改造 Checklist

1. **统一 request 封装**（示例，uni.request）：

```ts
async function request<T>(options: UniApp.RequestOptions): Promise<T> {
  const res = await uni.request(options);
  const body: any = res.data; // HTTP body 即信封

  // 例外：二进制/非 JSON 不走枚举（如 /files/*，通常直接用 URL，不会走这里）
  if (!body || typeof body !== 'object' || !('code' in body)) {
    throw new Error('响应格式异常');
  }

  if (body.code !== 2000) {
    if (body.code === 401) {
      // token 失效：清缓存 + 跳登录
    }
    uni.showToast({ title: body.message || '请求失败', icon: 'none' });
    throw Object.assign(new Error(body.message || '请求失败'), { body });
  }
  return body.data as T; // 成功：只取 data（可能为 null）
}
```

2. **不要用 `statusCode === 200` 判成功**：POST 成功是 201（`checklist/reorder`、`checklist/delete`、`me/delete` 除外，为 200）。
3. **`data` 可能为 `null`**（删除、排序类），取用时 `?? {}` / `?? []` 兜底。
4. **数组也在 `data` 内**：如列表 `body.data.items`、`body.data.list`。
5. **stats 附加字段**：`dashboard` 的 `range` 在 `data.range`；其余 stats 的 `range` 与 `data` 平级（`body.range`）。
6. **昵称检查**：外层 `code=2000`，业务结果看 `data.available` / `data.code`。
7. **游记生成门槛**：捕获 `code === 'GUIDE_NOT_READY'`，用顶层 `reason`、`stats` 引导用户。
8. **高德异常**：`code === '40030'`，`message` 已是修复提示（Key/配额），可原样展示。
9. **限流**：`code === 429` 时提示「请求过于频繁」，避免连续重试。
10. **错误 toast**：直接展示 `message`（已中文化），无需前端再映射文案。
