# 前端对接 · 地点与记录时间（2026-08-18）

> **Base**：`/dream/v1` · JWT · **勿传 userId**  
> 覆盖：添加预定点、新建记录、保存地点后自动生成时间线记录

---

## 0. 一句话

「关联日期」+「预计时间」在前端拼成**一个字符串**，字段名一律叫 **`recordedAt`**。

```text
2026-09-18 00:00:00
```

| 场景 | 接口 | 字段 |
|------|------|------|
| 添加 / 保存预定点 | `POST /journeys/plan/save` | `places[].recordedAt` |
| 读预定点 | `POST /journeys/plan/get` | `places[].recordedAt` |
| 新建记录 | `POST /journeys/entries/sync` | `entries[].recordedAt` **必填** |

**不要传**：`dayIndex`、`visitTime`、`createdAt`。

`createdAt` 是入库时间，后端自动写成当前时刻，请求体里没有这个字段。

---

## 1. 时间格式

**唯一合法格式**：`YYYY-MM-DD HH:mm:ss`（中间空格，必须带秒）

```text
✅ 2026-08-09 11:49:00
✅ 2026-09-18 00:00:00
❌ 2026-09-18T00:00:00.000Z
❌ 2026-09-18 00:00
❌ 不传（新建记录）
```

非法 → `{ "code": "40001", "message": "recordedAt 格式应为 YYYY-MM-DD HH:mm:ss" }`

UI 拼法：选「第 1 天 · 8/9」+「11:49」→ `"2026-08-09 11:49:00"`。没选具体钟点就用当天 `00:00:00`。

新建记录的 `recordedAt` 还须落在旅程起止日范围内（前后各放宽 1 天），否则 `40001`：「记录时间需在旅程日期范围内」。

## 2. 添加地点

```http
POST /dream/v1/journeys/plan/save
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
  "journeyId": "j_xxx",
  "places": [
    {
      "clientId": "p_1",
      "name": "武侯祠",
      "recordedAt": "2026-08-09 11:49:00",
      "lat": 30.646,
      "lng": 104.048,
      "locationName": "武侯祠",
      "category": "SIGHT",
      "intent": "planned"
    },
    {
      "clientId": "p_2",
      "name": "只写了个地名",
      "recordedAt": "2026-08-09 14:00:00"
    }
  ]
}
```

`plan/save` 仍是 **places 全量保存**：列表以本次 body 为准。改某个点的时间时，把该点完整带上。

### 读回

```http
POST /dream/v1/journeys/plan/get
{ "journeyId": "j_xxx" }
```

`places[]` 每项带回 `recordedAt`（同格式）。`dayIndex` 若出现，是服务端按旅程 `startDate` 算出来的第几天，**写的时候不必传、不要当写字段**。

创建旅程 `POST /journeys/create` 内嵌 `places[]` 同样用 `recordedAt`。

---

## 3. 保存地点后自动生成记录

带了 `recordedAt` 的预定点，`plan/save`（以及创建时内嵌地点、开始旅程补漏）会**幂等**插入一条时间线记录。

| 预定点 | 生成的记录 |
|--------|------------|
| 有 `lat` / `lng` | `type = location`，正文为空，带地点坐标和名称 |
| 没有坐标 | `type = text`，正文为地点 `name` |

记录上：

| 字段 | 谁填 | 含义 |
|------|------|------|
| `recordedAt` | 来自地点的 `recordedAt` | 这条记的是哪天几点（时间线按这个排） |
| `createdAt` | 后端入库自动 | 什么时候写入的 |
| `payload.source` | 后端 | `"plan_place"`，可用来区分占位打卡 |
| `payload.placeClientId` | 后端 | 对应 `places[].clientId` |

同一地点只生成一次（按地点 `clientId` 去重）。再 save / 再开始旅程**不会翻倍**。删预定点**不会**自动删这条记录。

拉记录：`POST /journeys/entries/list`，按 `recordedAt` 升序，出现在对应那天。

## 4. 新建记录

```http
POST /dream/v1/journeys/entries/sync
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
  "journeyId": "j_xxx",
  "entries": [
    {
      "clientId": "e_local_1",
      "type": "text",
      "content": "到武侯祠了",
      "recordedAt": "2026-09-18 00:00:00",
      "location": {
        "name": "武侯祠",
        "lat": 30.646,
        "lng": 104.048
      }
    }
  ]
}
```

`entries[].recordedAt` **必填**。同一 `clientId` 再 sync 会用本次时间覆盖，不插第二份。

已有记录改时间：`POST /records/update` 或 `POST /records/time`（仍可带 `recordedAt`）。

兼容 path：`POST /journeys/:id/entries/sync`。

## 6. 验收

- [ ] 地点 save 带 `recordedAt`，get 原样读回  
- [ ] 有坐标的点 → 时间线多一条地点记录，时间等于 `recordedAt`  
- [ ] 无坐标的点 → 时间线多一条文本记录  
- [ ] 再 save 同一 `clientId` → 记录条数不增加  
- [ ] 记一笔不传 `recordedAt` → 校验失败  
- [ ] 记一笔传 `2026-09-18 00:00:00` → 出现在对应天
